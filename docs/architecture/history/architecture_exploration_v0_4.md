# 自组织 Agent 能量场架构：工程探索规格 v0.4

## 0. 文档状态

本文是一份可证伪的研究架构，不是生产系统设计，也不代表这些机制已经成立。

v0.4 相对 v0.3 的主要变化：

1. 新增对称性破缺的三层来源分析（Section 7.0）；
2. 侧向抑制给出 O(Nd) 覆盖矩阵近似，并明确 N 的目标范围与适用边界；
3. 任务残差 D_t 的可计算性问题从"待解决"提升为 Experiment 0 的核心风险，拆分为 0a（合成任务）和 0b（LLM 提取需求）；
4. 新增 Verifier 错误的兜底机制：信用暂缓与回滚；
5. 新增组织级失败模式：死锁链、影子层级、语义收敛、级联失败；
6. 三层结构补充操作协议：提升协议、一致性规则、冲突处理；
7. 任务分解责任明确化；
8. 新增 Experiment 1.5（最小真实模型验证），缩短无模型阶段风险；
9. Baseline 定义补充公平预算协议；
10. 新增 Demo Task 定义；
11. 信用公式与影子价格的关系明确化；
12. 再分配增加份额上限护栏；
13. 新增与 MoE 的关系分析。

它综合了以下核心想法：

1. Agent 不应只能由预设角色和固定工作流组织；
2. Agent 可以从相近初态出发，根据任务需求动态分化；
3. 对称性破缺不需要随机初始化状态，来自第一轮任务分配的输入差异、通信图拓扑位置和执行历史三个层面；
4. 计算资源有限，分工和组织结构应由资源流塑造；
5. 任务路由只是外部能量的第一次注入，执行反馈必须参与后续能量再分配；
6. 任务表示与任务反馈应共享同一套任务指标和状态坐标；
7. 分化初期应使用反转路由和容量约束，避免早期随机优势演化成马太效应；
8. 历史有效的分工、通信和转换路径可以形成可修正的组织记忆；
9. hidden-state 通信、异构对齐和完整"能量货币"都属于待验证研究问题，而不是当前前提。

当前工程边界：所有探索都位于本独立目录，不与 OpenPilot 主运行时、权限系统或 metadata 合同集成。

## 1. 架构核心命题

### 1.1 总命题

将多 Agent 系统视为一个开放的资源转换系统：外部任务、环境和用户向系统提供目标、信息和计算预算；Agent 消耗资源、产生证据和产物；环境反馈改变任务状态；系统根据可验证贡献重新分配后续预算，并由此形成、维持或重塑组织结构。

简化循环如下：

```text
外部目标与真实预算
        ↓
任务分解与需求坐标生成
        ↓
任务状态与任务残差
        ↓
对称性破缺（第一轮输入差异 + 拓扑位置 + 执行历史）
        ↓
分化、路由与预算配置
        ↓
Agent 执行、通信与工具作用
        ↓
产物改变环境和已知状态
        ↓
验证、反馈与信用归因（含暂缓与回滚）
        ↓
更新任务残差、能力估计和组织结构
        ↓
继续注入、重新配置、冷却或终止
```

### 1.2 当前最小研究命题

在不降低任务质量的前提下，反馈驱动的连续分化和预算再分配，能否比固定角色、固定均分或简单贪心策略获得：

- 更完整的任务覆盖；
- 更少的重复工作；
- 更高的单位资源收益；
- 更好的环境适应性；
- 可接受的控制成本与稳定性。

### 1.3 不应提前宣称的结论

当前不宣称：

- 场动力学能够替代完整 Agent runtime；
- 平均场已经把复杂度从 `O(N²)` 降为 `O(N)`；
- 向量分散等价于有效分工；
- hidden-state 通信天然优于结构化文本；
- 所有资源和价值都能被无损压缩成一个通用标量；
- 系统已经具备生物意义上的生命、自主性或真正代谢。

## 2. 世界模型：开放系统而非封闭状态机

系统必须从外部获得：

- 目标和约束；
- 初始事实与环境状态；
- 计算、时间、工具访问等真实资源；
- 执行结果和验证信号；
- 必要时的用户评价与新增任务。

因此它不是能够自行产生能量的封闭系统。它可以做的是：

1. 记录能量从哪里进入；
2. 决定能量流向哪些 Agent 和任务维度；
3. 记录能量经过怎样的转换过程；
4. 测量转换后任务状态发生了什么变化；
5. 根据反馈调整下一轮资源配置；
6. 保存或淘汰有效的转换路径。

这里的"自组织"指内部配置策略能够适应任务和反馈变化，不表示系统脱离外部目标、预算与安全边界。

## 3. 能量概念的分层

"能量"必须拆成不同层次，否则同一个词会同时指算力、价值、信用和注意力，无法形成可验证模型。

### 3.1 第一层：真实资源

真实资源是会被消耗、具有单位并可记账的量，例如：

- 输入与输出 token；
- GPU/CPU 时间；
- 墙钟时间；
- 内存和通信字节；
- 工具调用次数；
- 货币成本；
- 人工审核时间；
- 风险额度。

真实资源不必全部转换成一个单位。底层优先使用向量账本：

\[
R_t=(tokens, gpu\_seconds, wall\_time, bytes, money, risk, \ldots)
\]

### 3.2 第二层：任务势能或任务残差

任务势能不是物理能量，而是当前状态距离目标状态还有多远。

令：

- \(G\)：目标和约束；
- \(S_t\)：在时刻 \(t\) 已被证据支持的任务状态；
- \(D_t=Residual(G,S_t)\)：尚未满足的任务需求。

Agent 的产物只有在改变 \(S_t\) 并减少 \(D_t\) 时，才产生可观察的任务进展。

### 3.3 第三层：贡献信用

贡献信用表示某个 Agent、证据、工具调用或通信边对任务进展的边际贡献。信用不是新产生的计算能量，而是一种影响未来资源分配的记账凭证。

### 3.4 第四层：有效能量价格

如果调度器需要把多维资源和贡献临时转换成一个可比较分数，应使用与当前任务状态有关的动态投影：

\[
E_{effective}(t)=p_t^\top R_t
\]

\(p_t\) 类似当前任务下的动态交换率或影子价格。例如任务临近截止时，时间成本权重会上升；事实不足时，新证据价值会上升；高风险操作前，验证资源价值会上升。

因此，"统一能量货币"在当前架构中的可行定义是：

> 底层保留多维、带来源和转换路径的资源账本；上层根据任务状态产生动态结算价格，用于局部决策，而不是把世界永久压缩成一个固定标量。

### 3.5 一碗米饭所揭示的问题

一碗米饭不能只由热量描述。它包含太阳、水、土壤、养分、土地、时间、劳动、知识、机械、运输、储存、烹饪和损耗；食用后又会根据人的身体状态转换为活动、组织修复、储存、热量和废物。

它说明：

- 资源具有类型、来源、品质和时间属性；
- 每次转换都有条件、效率、产物和损耗；
- 同一资源对不同接收者具有不同的边际作用；
- 物理守恒、经济成本和目标价值不是同一个量；
- 一个最终数字无法反向恢复完整因果链。

Agent 系统不需要先解决世界范围的一般能量建模，才能开始实验。最小探索只需在局部任务内明确资源单位、转换过程、任务残差和结算规则。

### 3.6 影子价格与信用公式的关系

Section 3.4 的影子价格 \(p_t\) 和 Section 8.3 的信用公式权重 \(w_d, w_k, w_r, w_s\) 不是两套独立参数。关系如下：

- \(p_t\) 是资源维度的动态交换率（token 值多少、时间值多少）；
- 信用公式中的权重是任务维度的动态重要性（贡献值多少、冗余罚多少、风险罚多少）；
- 两者通过任务残差 \(D_t\) 耦合：\(D_t\) 中较大的维度意味着对应需求更紧迫，因此对该维度贡献的信用权重更高。

具体地，信用公式的权重不应是手动设定的常数，而应从当前任务状态导出：

\[
w_d(t) = f(D_t), \quad w_k(t) = p_t^{(tokens)}, \quad w_r(t) = g(Coverage_t), \quad w_s(t) = h(RiskField_t)
\]

其中 \(f, g, h\) 是待校准的映射函数。第一阶段可以使用固定权重作为 baseline，但必须与从任务状态导出的动态权重进行比较，验证动态权重是否带来可测量的收益。

## 4. 任务表示与反馈的统一

### 4.1 它们是同一状态空间的两个方向

任务表示回答：

> 当前目标是什么？哪些需求仍未满足？

任务反馈回答：

> 执行后，哪些需求被满足、恶化或暴露出新的缺口？

因此二者必须使用同一套指标坐标，而不是 Router 产生一套任务 embedding、Verifier 再产生一个无关总分。

### 4.2 最小任务状态

一个任务状态至少包含：

```text
Goal
  ├─ requirements       需求及权重
  ├─ constraints        不允许违反的条件
  ├─ acceptance_rules   完成判定
  └─ resource_limits    总预算和风险边界

ObservedState(t)
  ├─ supported_facts    有证据支持的事实
  ├─ artifacts          已产生的产物
  ├─ verified_results   验证结果
  ├─ conflicts          未解决冲突
  └─ uncertainty        未知或低可信区域

Residual(t)
  ├─ unmet_requirements
  ├─ unresolved_risks
  ├─ missing_evidence
  └─ new_requirements
```

### 4.3 反馈更新

执行动作 \(A_i(t)\) 后：

\[
(S_t,R_t) \xrightarrow{A_i} (S_{t+1},R_{t+1},Artifacts,Evidence)
\]

Verifier 不直接奖励"生成了多少内容"，而是根据证据更新任务状态：

\[
D_{t+1}=Residual(G,Update(S_t,Evidence,Artifacts))
\]

任务进展可以写成多维变化：

\[
\Delta D_t=D_t-D_{t+1}
\]

如果产生了新的风险或需求，对应维度可以为负或新增，不能强行认为每轮执行都让任务单调变好。

### 4.4 反馈可信度层级

反馈来源具有不同权威级别：

1. 可重复环境事实，如编译、单元测试、传感器读数；
2. 形式规则和静态检查；
3. 独立模型或多评审一致性；
4. Agent 自评；
5. 用户偏好或开放式评价。

反馈记录必须保存来源、证据、置信度和适用范围。低可信反馈可以影响探索，但不应直接覆盖高可信事实。

### 4.5 Verifier 错误的兜底机制

Verifier 不完美是常态而非异常。系统必须能在 Verifier 给出错误判断后继续运作，而不是让错误信用固化。

**信用暂缓（Credit Pending）**

通过验证的信用不立即 commit，而是先进 pending 态：

\[
Credit_i(t) \to Pending_i(t, \text{confidence}, \text{source\_authority})
\]

commit 条件（满足任一，取最早者）：

- 经过 \(N_{settle}\) 个 cycle 后无矛盾证据出现；
- 更高权威级别的验证确认（如环境测试通过、用户确认）；
- 任务结束时最终验收。

commit 前如果出现矛盾证据，pending 信用被削减或清零，不进入已 commit 信用池。

**信用回滚（Credit Rollback）**

当后续证据推翻之前的 Verifier 判断时，沿依赖图回溯：

1. 发现 EvidenceNode \(e_k\) 与事实矛盾；
2. 找到所有依赖 \(e_k\) 的 FeedbackNode；
3. 找到这些 FeedbackNode 对应的已 commit 信用；
4. 按依赖路径比例扣减相关 Agent 的信用；
5. 更新这些 Agent 的能力估计不确定性 \(U_i\)（增大）。

回滚不退还已消耗的真实资源——那些已经花了。它只调整信用值，影响后续预算分配。

**错误 Verifier 的检测信号**

以下现象提示 Verifier 可能系统性出错：

- 某个 Agent 的 pending 信用远高于 commit 信用（大量验证无法被更高权威确认）；
- 回滚频率随时间上升；
- 多个独立 Agent 对同一事实给出矛盾证据，但 Verifier 只采信一方。

检测到这些信号时，系统应降低该 Verifier 来源的权威级别，或触发人工审核。

### 4.6 任务分解责任

任务分解——将目标拆成需求维度——是系统的第一个关键操作，必须在文档中明确责任归属。

**分解者：Router（或独立的 Planner 角色）**

- Router 负责将任务目标分解为带名称的需求向量 \(r = (r_1, r_2, \ldots, r_d)\)；
- 在无模型阶段，需求向量是人工定义的；
- 在本地模型阶段，由 LLM 从任务描述中提取候选需求，但必须映射回可评估的离散需求集合。

**分解的完备性问题**

分解可能不完备——执行过程中出现新的需求维度。处理方式：

1. 新需求作为新维度追加到需求向量，历史状态在该维度上值为"未知"而非"已满足"；
2. 任务残差在该维度上初始化为最大值（完全未满足）；
3. 已有 Agent 的分配倾向向量在该维度上初始化为零（无倾向）；
4. 触发重新分化或局部路由调整，不需要全量重算。

**不完备分解的检测**

- 多个 Agent 独立产出了不属于任何已知需求维度的证据；
- 任务残差在所有已知维度上已趋近零，但用户或环境反馈表明任务未完成；
- Agent 行为出现无法归类的产物。

检测到不完备分解时，Router 应追加需求维度并通知所有 Agent，而不是忽略这些信号。

## 5. Agent 与组织状态

### 5.1 Agent 最小状态

每个 Agent \(i\) 的研究状态暂定为：

\[
Z_i(t)=\{C_i,A_i,Q_i,U_i,B_i,H_i\}
\]

- \(C_i\)：长期或跨任务的能力先验；
- \(A_i\)：当前任务上的分配倾向；
- \(Q_i\)：在各任务需求上的观测效用；
- \(U_i\)：能力和效用估计的不确定性；
- \(B_i\)：当前真实资源余额；
- \(H_i\)：缓慢变化的历史身份或关系状态，可选。

必须区分"Agent 想承担什么""Router 给它什么"和"它实际擅长什么"。Capability vector 不能同时承担以上所有语义。

### 5.2 Identity 的修正

原方案声称 capability 与 identity 正交，但动量跟随公式只产生快慢变量，不保证数学正交。

当前定义改为：

> Identity 是用于跨周期稳定识别和关系建模的慢状态；只有实验证明通信拓扑需要它时才保留。

Identity 不能单独决定通信，因为相似身份更容易形成同质连接，而任务协作通常需要能力互补和产物依赖。

### 5.3 转换函数比角色标签更核心

Agent 的价值可以表达为条件转换能力：

\[
T_i:(Input,State,Resources)\rightarrow(Artifacts,Evidence,StateChange,Cost,Loss)
\]

系统真正要学习的是：在当前状态下，哪个 Agent 能用何种成本把哪些输入转换成多少可验证任务进展，而不是给 Agent 贴上永久角色名称。

## 6. 三层组织结构

### 6.1 细胞内树层

职责：保存单 Agent 私有状态和局部执行过程。

包含：

- 当前需求和局部计划；
- 私有工作记忆；
- 工具输入输出；
- 局部置信度；
- 资源余额与成本；
- 尚未共享的候选证据。

该层保持树形或嵌套 metadata，不因场模型而强制图化。

### 6.2 共享证据图层

职责：保存跨 Agent 可验证的事实、产物、依赖和贡献路径。

候选节点：

- RequirementNode；
- EvidenceNode；
- ArtifactNode；
- ActionNode；
- FeedbackNode；
- AgentSnapshotNode。

候选边：

- supports / contradicts；
- produced_by；
- consumed_by；
- depends_on；
- verified_by；
- contributed_to。

所谓节点"能态"在第一阶段只表示调度优先级或近期激活度，不能与节点内部真的保存模型 hidden states 混为一谈。

### 6.3 组织场层

职责：根据任务残差、群体状态和反馈形成控制信号。

包含：

- Task Residual Field；
- Population Capability Field；
- Redundancy/Inhibition Field；
- Resource Allocation Field；
- Risk and Constraint Field；
- Feedback/Credit Field。

场层输出的是分配倾向和控制参数，实际执行、审批、预算扣减与终止仍由离散控制器完成。

### 6.4 提升协议：从树层到图层

Agent 在私有执行中发现候选证据后，需要经过提升协议才能成为共享图节点。提升不是自动的——不是所有私有发现都值得共享。

**提升流程：**

1. **候选生成**：Agent 在树层标注候选证据，附带置信度和来源；
2. **冲突检查**：检查共享图中是否已存在支持或反对同一事实的节点；
3. **提升决策**：根据以下条件决定是否提升——
   - 置信度超过阈值（阈值由反馈可信度层级决定）；
   - 与已有图节点无冗余（或冗余度低于上限）；
   - 对任务残差有潜在影响（能减少某个未满足需求）；
   - 通信成本合理（证据的序列化大小不超过预算）；
4. **写入与通知**：写入图节点，建立与已有节点的边，通知可能受益的下游 Agent；
5. **验证与降级**：如果后续验证发现提升的证据有误，将节点标记为 contradicted，保留节点但降低其权重，并通知所有消费过该节点的 Agent。

**不提升的情况：**

- Agent 局部探索中的失败尝试（可作为私有教训保留，不提升为全局事实）；
- 低置信度的推测（保留在树层等待更多证据）；
- 与已有图节点高度冗余的信息。

### 6.5 图层一致性

多个 Agent 可能同时尝试提升冲突或冗余的证据。

**冲突处理规则：**

- 如果两个 Agent 同时提升同一事实的不同版本，先写入的节点保留，后写入的节点标记为 conflicts_with，两者都保留；
- Verifier 或更高权威的后续验证决定保留哪个、降级哪个；
- Agent 读取图节点时必须检查 contradicted 和 conflicts_with 标记，不能假设图中所有节点都可信。

**AgentSnapshotNode 的新鲜度**

AgentSnapshotNode 是 Agent 在图中的投影，用于让其他 Agent 了解"这个 Agent 当前在做什么"。它可能和 Agent 的实际私有状态不一致。

- AgentSnapshotNode 必须附带时间戳和版本号；
- 读取方应检查新鲜度——如果快照超过 \(T_{stale}\) 未更新，标记为 stale；
- Agent 有责任在状态发生显著变化时更新自己的快照（非强制，但场层可以根据 stale 快照降低对该 Agent 的路由优先级）。

## 7. 分化动力学

### 7.0 对称性破缺的来源

初始状态相同是本架构的设计目标——所有 Agent 从相近初态出发。但对称性必须在某个环节被打破，否则所有 Agent 会永远保持相同状态、做出相同选择。

破缺不需要在初始状态上做手脚。它来自三个层面，按时间顺序叠加：

**第一层：第一轮任务分配的输入差异（基因选择性表达）**

所有 Agent 初始状态相同，但第一个 cycle 它们收到的任务子需求不同。即使分配是随机的——Agent 1 拿到"写函数"、Agent 2 拿到"写测试"、Agent 3 拿到"写文档"——它们在执行完第一个动作后状态就不再相同了。

这对应生物学中的基因选择性表达：相同的基因库，因接收到不同的位置信号（morphogen 梯度），表达不同的基因组合，走向不同的分化路径。

在系统中：第一轮分配的差异不需要很大，只需要让不同 Agent 接触到不同的需求维度。后续的分化动力学放大这个初始微小差异。

**第二层：通信图中的拓扑位置（细胞器不均匀分布）**

即使两个 Agent 内部状态完全相同，它们在通信图中的位置不同——一个连接了 EvidenceNode A，另一个连接了 EvidenceNode B——它们能看到的信息不同，反应自然不同。

这对应生物学中细胞器的不均匀分布：即使两个细胞的基因和表达状态相同，它们在某一时刻的物理配置不同，导致对同一信号的反应不同。

在系统中，Agent 在图中的拓扑位置差异来自：

- 邻居不同 → 可见的共享证据不同；
- 资源余额不同（即使初始相同，第一个动作后就会不同）；
- 执行历史不同 → context window / KV cache 内容不同。

**第三层：执行历史导致的内部状态分化（表观遗传）**

随着 cycle 推进，每个 Agent 积累了不同的执行历史。这些历史改变了 Agent 的内部状态（context、局部记忆、能力估计），进一步放大差异。

这对应表观遗传修饰：不改变基因序列，但通过 DNA 甲基化、组蛋白修饰等方式改变基因表达模式，且这些改变可以随细胞分裂传递。

在系统中：Agent 的 \(C_i\)（能力先验）、\(Q_i\)（观测效用）、\(U_i\)（不确定性）都会随执行历史缓慢变化，形成持久的状态差异。

**设计含义：**

- 初始状态相同是可以保持的——不需要随机初始化 Agent 状态；
- 第一轮任务分配的差异性是主动设计的破缺来源——即使随机分配也有效；
- 通信图拓扑和执行历史是结构涌现的破缺来源——不需要额外设计；
- 分化动力学的任务是放大而非创造不对称性。

### 7.1 Phase 0 当前启发式

\[
A_i(t+1)=Norm(A_i(t)+\eta[
F_{task}^i+F_{cohesion}^i+F_{diversity}^i])
\]

其中：

\[
F_{task}^i=\beta(D_t-A_i)
\]

\[
F_{cohesion}^i=\gamma(\Phi-A_i),\qquad
\Phi=\frac{1}{N}\sum_i A_i
\]

\[
F_{diversity}^i=\frac{\lambda}{N-1}\sum_{j\ne i}
\exp\left(\frac{cos(A_i,A_j)-1}{\tau}\right)(A_i-A_j)
\]

它只是稳定、可执行的第一版假设，并非严格从某个全局损失推导出的最终方程。

### 7.2 侧向抑制的复杂度与近似

当前 \(F_{diversity}\) 的两两比较复杂度为 \(O(N^2d)\)。

**N 的目标范围**

- 无模型阶段：\(N \le 20\)，直接使用两两比较，复杂度可接受；
- 本地模型阶段：\(N \le 10\)（受 GPU 显存限制），两两比较无压力；
- 如果未来需要 \(N > 100\)，使用以下近似方案。

**覆盖矩阵近似（O(Nd)）**

核心思路：不比较 Agent 两两之间的关系，而是维护一个群体覆盖向量，每个 Agent 和覆盖状态比较。

定义群体覆盖矩阵：

\[
Coverage_k(t) = \sum_i A_{i,k}(t) \cdot Q_{i,k}(t)
\]

表示需求维度 \(k\) 上当前有多少有效覆盖（分配倾向 × 观测效用）。

侧向抑制改为：

\[
F_{diversity,k}^i = \lambda \cdot \sigma\left(\frac{Coverage_k - \theta_{sat}}{\tau}\right) \cdot (-A_{i,k})
\]

其中 \(\sigma\) 为 sigmoid，\(\theta_{sat}\) 为饱和阈值。当维度 \(k\) 的覆盖已饱和时，排斥力增大；未饱和时，排斥力趋近于零。

每个 Agent 只需读 \(Coverage\) 向量（\(O(d)\)），不需要和其他 Agent 逐个比较。总复杂度 \(O(Nd)\)。

**近似丢失了什么**

- 两两比较知道"具体是谁和谁重叠"，覆盖矩阵只知道"这个方向有多拥挤"；
- 对于路由和匹配——需要知道具体的配对关系——可能仍需两两比较；
- 覆盖矩阵近似适合"是否需要继续往这个方向分化"的判断，不适合"哪两个 Agent 应该建立通信边"的判断。

**中间方案：聚类近似**

把 Agent 聚成 \(K\) 个簇，簇间用覆盖矩阵，簇内用两两比较。复杂度 \(O(NKd + K^2d)\)。当 \(K \ll N\) 时接近 \(O(Nd)\)。

**当前选择**

Phase 0-1 直接使用两两比较（\(N \le 20\)）。如果实验表明需要扩展到更大 \(N\)，再实现覆盖矩阵近似并验证其损失是否可接受。

### 7.3 必须修正的目标

纯余弦排斥只会鼓励不同，不保证互补。最终目标更接近：

\[
J=
L_{uncovered}
+\lambda L_{redundancy}
+\mu L_{resource}
+\rho L_{risk}
+\xi L_{instability}
\]

需要将动力学方案与直接优化、贪心匹配和市场式分配比较。如果简单方法更稳定且效果相同，应接受场动力学没有额外工程价值。

### 7.4 收敛定义

不能用群体方差下降表示分化完成，因为从相近初态分化时方差可能上升。

候选收敛条件应同时包含：

- 状态更新量持续低于阈值；
- 分配关系在多个周期内稳定；
- 需求覆盖不再明显提高；
- 单位成本收益不再明显提高；
- 没有周期性振荡；
- 没有关键需求长期饥饿。

**收敛 vs 死锁的区分**

收敛和死锁在表面上相似——状态更新量低、分配稳定。区分条件：

- 收敛：需求覆盖不再提高**但已接近完整覆盖**，单位成本收益不再提高**但已处于可接受水平**；
- 死锁：需求覆盖不再提高**但存在未满足的关键需求**，单位成本收益不再提高**但有 Agent 处于空闲或等待状态**。

检测信号：

- 统计未满足需求维度数和它们的权重——如果高权重需求长期未满足，判为死锁而非收敛；
- 统计 Agent 的资源消耗率——如果多个 Agent 长时间不消耗资源但任务未完成，判为死锁；
- 检查通信图中是否存在循环等待链——A 等 B 的证据，B 等 C 的，C 等 A 的。

检测到死锁时，触发以下恢复措施之一：

- 向等待链中的某个 Agent 注入探索预算，强制尝试替代路径；
- 打破循环等待——让某个 Agent 放弃等待，转而处理其他需求；
- 如果死锁持续超过阈值，上报外部控制器，请求人工干预或任务重新分解。

## 8. 完整能量循环

### 8.1 外部注入

Energy Authority 根据任务价值、风险和总资源限制提供：

- 任务目标；
- 初始资源包；
- 每种资源的单位；
- 使用范围和过期条件；
- 是否允许后续追加预算。

任务路由本身不创造资源。

### 8.2 分配与消耗

令 \(B_i(t)\) 为 Agent 余额，\(G_i(t)\) 为本轮 grant，\(K_i(t)\) 为实际成本：

\[
B_i(t+1)=B_i(t)+G_i(t)-K_i(t)
\]

系统级检查：

\[
B_{system}(t+1)=B_{system}(t)+E_{in}(t)
-\sum_iK_i(t)-K_{router}(t)-K_{verifier}(t)-K_{communication}(t)
\]

已消耗的资源不能回收。未使用 grant 可以退回共享池；新增执行必须由尚未使用的共享预算或新的外部注入支付。

### 8.3 反馈与信用

候选局部信用：

\[
Credit_i(t)=
w_d(t)\cdot Contribution_i(\Delta D_t)
-w_k(t)\cdot Cost_i
-w_r(t)\cdot Redundancy_i
-w_s(t)\cdot Risk_i
\]

其中权重不从手动设定，而从当前任务状态导出（见 Section 3.6）：

- \(w_d(t) = f(D_t)\)：需求越紧迫的维度，贡献权重越高；
- \(w_k(t) = p_t^{(tokens)}\)：当前 token 的影子价格；
- \(w_r(t) = g(Coverage_t)\)：覆盖已饱和的方向，冗余惩罚更高；
- \(w_s(t) = h(RiskField_t)\)：当前风险水平越高，风险惩罚越高。

`Contribution` 不能只根据最后输出判断，而需要沿证据与依赖路径归因。

信用在 commit 前经过暂缓期（见 Section 4.5）。

### 8.4 再分配

下一轮资源份额使用带份额上限的 softmax 分配：

\[
Share_i(t+1)=\min\left(
\alpha,\;
Softmax\left(
\frac{\widehat{Credit_i}+Explore_i-Penalty_i}{T}
\right)
\right)
\]

\[
G_i(t+1) = Share_i(t+1) \cdot E_{available}(t+1)
\]

- `Credit`：已 commit 的历史信用（pending 信用不参与分配）；
- `Explore`：不确定性奖励和最低探索补贴；
- `Penalty`：冗余、风险、失败或违规；
- `T`：控制集中度的温度；
- `α`：份额上限（如 0.5），防止任何单 Agent 独占预算。

**温度调度**

\(T\) 不应是固定常数。建议：

- 早期：\(T\) 较高，鼓励分散探索；
- 中期：\(T\) 逐渐降低，加强信用信号的影响；
- 后期：\(T\) 较低但非零，保留少量探索；
- 环境变化时：\(T\) 临时升高，重新探索。

温度调度本身有超参数，需要在 Experiment 3 中与固定温度比较，验证动态温度是否带来可测量的收益。

### 8.5 三种反馈时间尺度

| 时间尺度 | 主要来源 | 主要作用 |
|---|---|---|
| 周期内 | 工具结果、新证据、冲突、局部测试 | 更新当前残差并重新路由 |
| 任务结束 | 最终验收、整体质量、用户评价 | 计算组织与贡献路径的最终信用 |
| 跨任务 | 相似任务长期表现、失败和负迁移 | 更新能力先验、热启动和路由参数 |

## 9. 反转路由与马太效应控制

### 9.1 马太效应来源

如果任务始终选择当前得分最高的 Agent：

```text
早期随机领先
→ 获得更多任务和预算
→ 获得更多被观察与成功的机会
→ 评分进一步上升
→ 其他 Agent 无法证明能力
```

这会把观测机会误当成真实能力。

### 9.2 早期：反转路由

分化初期让 Agent 从任务需求池中选择工作，而不是让任务只选择当前赢家：

- 每个 Agent 有最低探索预算；
- 每个 Agent 有容量上限；
- 每个需求允许有限数量的重复探索；
- 未知能力方向获得不确定性补贴；
- 当前高分 Agent 不能占据全部高价值需求。

反转路由解决的是"获得验证机会"的公平性，不直接解决信用归因。

### 9.3 中期：双向约束匹配

- 任务根据历史效用偏好 Agent；
- Agent 根据能力倾向和探索价值偏好需求；
- Router 在覆盖、容量、风险和成本约束下求匹配；
- 对不确定或高风险需求保留有限竞争。

### 9.4 后期：任务主导利用

- 剩余任务需求选择预计边际收益最高的 Agent；
- 强化冗余抑制；
- 停止为低贡献路径分配主预算；
- 保留少量探索预算，以处理环境变化或估计漂移。

### 9.5 阶段切换条件

不使用固定 Cycle 数作为唯一切换条件。切换依据包括：

- 能力估计不确定性是否下降；
- 任务需求是否已被初步覆盖；
- Agent 相对转换效率是否可区分；
- 分配是否趋于稳定；
- 是否出现需求突变或新证据。

环境变化时，系统可以从利用阶段重新回到探索或匹配阶段。

## 10. 通信拓扑

### 10.1 通信边的形成依据

通信不能只依赖 identity 或 capability 相似度。候选边权应考虑：

- 发送方产物类型；
- 接收方当前输入需求；
- 子任务依赖方向；
- 证据可信度；
- 历史信息增益；
- 通信成本；
- 重复和风险。

### 10.2 通信是否有价值的判定

必须通过消融验证：

- 删除消息后下游质量是否下降；
- 打乱发送方后结果是否变化；
- 接收方是否引用或使用了关键证据；
- 通信收益是否覆盖 token、时延和带宽成本。

图变得稀疏或有向，不自动等于通信有效。

### 10.3 阶段化通信假设

- 早期：低成本广播任务残差和公共事实；
- 中期：按产物—需求兼容性建立候选边；
- 后期：只传递下游明确需要的证据与产物；
- 冷却后：保留可审计文本/结构化证据，不默认长期保存 hidden state。

## 11. 本地模型和 latent communication

### 11.1 本地模型引入时机

无模型阶段先验证分化、反馈、预算和信用机制。只有这些机制至少优于简单基线，才引入本地模型。

第一轮建议：

- 一个约 0.5B–3B decoder-only 模型；
- 多个逻辑 Agent 共用相同权重和 tokenizer；
- 固定模型版本、推理精度和随机配置；
- 先使用结构化 JSON 通信；
- 暂不处理异构模型对齐。

### 11.2 本地模型第一阶段职责

模型首先只用于：

- 从任务描述提取候选需求；
- 从产物提取候选事实和证据；
- 将反馈映射回任务残差坐标；
- 在明确分工下执行可自动评分的微型任务。

模型输出必须经过结构验证或环境验证，不能把自评直接当成信用。

### 11.3 latent communication 对照组

| 组别 | 通信方式 |
|---|---|
| A | 无通信 |
| B | 结构化 JSON |
| C | 文本摘要 |
| D | pooled embedding |
| E | hidden state 或 KV 注入 |

需要统一比较任务质量、端到端时延、峰值内存、通信字节、生成 token、失败率和可审计性。

只有同构 latent 通信稳定优于结构化文本，并通过删除和置换消融证明消息被真正使用，才进入异构模型对齐。

## 12. 组织记忆与热启动

组织快照候选内容：

- 任务需求与环境条件；
- Agent 能力后验及其不确定性；
- 有效分工和通信路径；
- 能量成本与任务收益；
- 失败模式和负迁移记录；
- Router 与 Verifier 配置版本。

热启动不能使用未经校准的固定阈值。必须验证：

- 相似度是否预测了正迁移；
- 加载旧组织后是否更快；
- 最终质量是否下降；
- 发现不适配后能否退回冷启动；
- 历史赢家是否压制新生态位。

记忆不是永久固化骨架，而是具有证据、适用范围、衰减和撤销条件的路由先验。

## 13. 组织级失败模式

除 Agent 级失败（gaming、drift、负迁移）外，系统还存在组织级失败模式。这些模式不源于单个 Agent 的行为，而源于多个 Agent 之间的交互结构。

### 13.1 死锁链

A 等 B 的证据，B 等 C 的，C 等 A 的。在场动力学里表现为系统进入一个低能量但无进展的稳态。

**检测：** 见 Section 7.4 的收敛 vs 死锁区分条件。

**恢复：** 向等待链注入探索预算、打破循环等待、上报外部控制器。

### 13.2 影子层级

某个 Agent 因为路由能力强（不是任务能力强），变成了事实上的中央调度器。其他 Agent 都通过它间接获得任务和证据。自组织退化为隐式中央集权。

**检测信号：**

- 通信图中某个 Agent 节点的入度或出度远高于平均值（如 > 3 倍标准差）；
- 移除该 Agent 后，剩余 Agent 的任务分配显著恶化；
- 该 Agent 的实际任务产出质量不高，但通信量很高。

**应对：**

- 对通信度设立容量上限——任何 Agent 的通信带宽超过阈值时，Router 应将部分通信重路由到其他 Agent；
- 在信用计算中区分"任务贡献"和"路由贡献"——后者不应获得与前者同等的资源分配权；
- 如果路由贡献确实有价值，考虑将其显式化为一个独立的 Router 角色，而不是让某个 Agent 隐式承担。

### 13.3 语义收敛（Groupthink）

共享证据图太高效，所有 Agent 都看到同样的证据，思路趋同。"减少冗余"退化为"减少探索"。

**与有效分工的区别：** 有效分工是 Agent 在不同需求维度上专业化，但在各自维度上有深度探索。Groupthink 是所有 Agent 在所有维度上给出相似的浅层产出。

**检测信号：**

- 不同 Agent 的产物在语义层面的重叠度持续上升；
- 移除某个 Agent 后任务质量几乎不变（说明它没有独特贡献）；
- 新证据出现的速率随时间下降，但任务残差未趋近零。

**应对：**

- 维持最低探索预算，即使所有 Agent 看起来已经收敛；
- 有意限制共享图的信息传播——不是所有证据都广播给所有 Agent，部分证据只传递给按需请求的 Agent；
- 将"多样性下限"作为收敛条件之一——如果 Agent 间相似度超过阈值，不判定为收敛，而是判定为 groupthink 并重新注入探索。

### 13.4 级联失败

一个关键 Agent 崩溃（超时、OOM、返回错误），依赖它的下游 Agent 全部阻塞，信用链断裂，整个组织在几个 cycle 内瓦解。

**检测信号：**

- 某个 Agent 连续 \(N_{fail}\) 个 cycle 无产出；
- 该 Agent 在通信图中有大量下游消费者；
- 下游 Agent 开始出现资源消耗率骤降。

**应对：**

- 每个关键证据节点应有至少两个独立来源（冗余不只是浪费，也是鲁棒性）；
- Agent 崩溃时，其 pending 信用清零，已 commit 信用冻结，其下游消费者获得探索预算以寻找替代路径；
- 系统级检查：如果级联导致超过 \(\beta_{cascade}\) 的 Agent 在 \(T_{cascade}\) 内停止产出，触发降级模式——简化任务分解、减少 Agent 数量、或上报外部控制器。

## 14. 与 MoE（Mixture of Experts）的关系

本架构与 MoE 有结构相似性，理解异同有助于定位贡献和避免重复造轮子。

### 14.1 结构对比

| 维度 | MoE | 本架构 |
|---|---|---|
| Expert 形态 | 不可变的网络参数 | 完整的 Agent（有状态、有工具、有记忆） |
| 分化来源 | 训练阶段学习 | 运行时动态分化 |
| Router | 学习的线性层 | 场动力学 + 反馈驱动 |
| 路由对象 | token → expert | 需求维度 → Agent |
| 容量约束 | expert capacity (tokens/cycle) | Agent 预算和容量上限 |
| 负载均衡 | auxiliary loss (Expert Choice / Token Choice) | 反转路由 + 份额上限 + 探索补贴 |
| 反馈信号 | task loss 梯度回传 | 多层级反馈（环境验证、信用归因） |
| 时间尺度 | 训练时一次性分化 | 每个任务周期内动态分化 |

### 14.2 本架构在什么情况下可能比 MoE 更合适

- 任务需要多步骤推理和工具调用，而非单次前向传播；
- Agent 需要有状态的执行（工作记忆、执行历史），而非无状态的参数变换；
- 分工需要在运行时动态调整，而非在训练后固定；
- 任务分解本身是不确定的，需要在执行中发现新需求。

### 14.3 本架构在什么情况下不如 MoE

- 任务可以被很好地压缩成单次前向传播；
- 分工模式在大量任务间是稳定的（训练一次即可复用）；
- 对延迟敏感——MoE 的路由是矩阵乘法，本架构的场动力学需要多轮迭代；
- 任务分解是明确的、不变的。

### 14.4 需要回答的关键问题

Section 7.3 已经提出：如果直接优化目标 \(J\) 比场动力学更稳定且效果相同，应接受场动力学没有额外工程价值。

类似地，需要回答：如果用 MoE 风格的学习型 router（一个小型网络，输入任务状态和 Agent 状态，输出分配概率）比场动力学更稳定且效果相同，应接受场动力学没有额外工程价值。

这两个比较应在 Experiment 1 中作为 baseline 包含进去。

## 16. 工程探索路线与待证明命题

每个阶段只回答有限问题。前一阶段失败时，不因为愿景完整而自动进入后一阶段。

### Experiment 0a：合成任务的状态合同

**做什么**

- 人工定义 3-5 个完全可计算的模拟任务，每个任务有手写的需求向量；
- 定义目标、观测状态、任务残差和反馈事件；
- 为状态更新编写不变量和属性测试；
- 验证同一产物在相同状态下得到一致反馈；
- 验证任务残差能正确解释任务的完成和未完成状态。

**要证明**

> 在需求向量已知且残差可精确计算的前提下，任务表示和反馈能否使用同一坐标一致地更新。

**失败条件**

- 同一产物在相同状态下得到不一致反馈；
- 任务残差无法解释为什么完成或未完成；
- 新证据无法追溯到状态变化。

**性质**

此实验验证管道畅通，不验证需求提取质量。如果失败，说明状态合同设计有缺陷，需要重新定义，不是后续实验能修复的。

### Experiment 0b：LLM 提取需求向量

**做什么**

- 选 5-10 个自然语言描述的编程任务（从简单到中等复杂度）；
- 用 LLM 从任务描述中提取候选需求向量；
- 与人工标注的 ground truth 需求向量比较；
- 测量提取的稳定性——同一任务多次提取的结果差异；
- 测量提取的完备性——是否遗漏关键需求维度；
- 测量提取的粒度——需求维度是否过细或过粗。

**要证明**

> LLM 能否从自然语言任务中稳定提取足够完备的需求向量，映射回可评估的离散需求集合。

**失败条件**

- 同一任务多次提取的需求向量差异过大（不稳定）；
- 遗漏关键需求维度的频率超过阈值（不完备）；
- 需求维度粒度不可控（过细导致维度爆炸，过粗导致无法区分）。

**失败后的应对**

- 不放弃整个架构，但限制任务范围——只在需求可人工预定义的任务类型上使用；
- 或改进提取 prompt 和验证流程，重试一次；
- 如果 LLM 提取始终不可靠，接受 Experiment 0a 的合成任务作为主要验证场景，将开放式任务作为未来工作。

### Experiment 1：无模型分化

**做什么**

- 比较以下 baseline——
  - **B0：单 Agent + 全部预算**（最强 baseline，如果多 Agent 打不过它，多 Agent 本身没有收益）；
  - B1：N 个独立 Agent，最终投票或选择；
  - B2：随机分配；
  - B3：固定角色（手工设计专家角色）；
  - B4：贪心覆盖（每次选当前边际收益最高的分配）；
  - B5：场动力学但无侧向抑制；
  - B6：完整场动力学；
  - B7：学习型 router（小型网络，输入任务和 Agent 状态，输出分配概率）——验证场动力学是否优于简单学习型路由；
- 扫描 Agent 数（3, 5, 10, 20）、需求维度（3, 5, 10）和动力学参数；
- 使用多随机种子和非均匀需求；
- 检测坍缩、分散、振荡与需求饥饿。

**公平预算协议**

所有配置使用相同的总 token 预算和总墙钟时间上限。单 Agent baseline 使用 \(N \times\) 单 Agent 预算。多 Agent 配置中每个 Agent 使用 \(1 \times\) 单 Agent 预算。如果单 Agent 因 context window 限制无法用完 \(N \times\) 预算，记录实际消耗量，并在报告中说明。

**要证明**

> 连续分化能否在维持覆盖的同时减少冗余，并优于包括单 Agent 在内的所有简单基线。

**停止条件**

如果 B6 不能稳定优于 B0（单 Agent）或 B4（贪心），不进入复杂 LLM 分化。如果 B7（学习型 router）优于 B6（场动力学），接受场动力学没有额外工程价值。

### Experiment 1.5：最小真实模型验证

**做什么**

- 部署一个 0.5B-3B 同构小模型；
- 使用 3 个 Agent 实例；
- 选择一个简单的可自动评分的编程任务（如"实现一个有 5 个 TODO 的 Python 函数"）；
- 手动设置任务残差（不依赖 LLM 提取）；
- 运行分化动力学 3-5 个 cycle；
- 观察：Agent 的分配倾向是否产生了有意义的差异？Agent 的实际行为是否与分配倾向一致？

**要证明**

> 模拟阶段假设的"Agent 有不同的转换效率"在真实模型下大致成立——同一模型的不同实例，在不同输入和执行历史下，确实表现出可区分的任务表现。

**失败条件**

- 3 个 Agent 的行为几乎相同，分配倾向的差异不导致实际行为差异；
- 真实模型的转换效率波动太大，无法被场动力学捕捉。

**性质**

此实验是 go/no-go 检查。如果失败，说明无模型阶段的结论可能不迁移到真实模型，需要重新评估架构假设或调整模型使用方式（如使用不同 prompt 而非相同 prompt + 不同输入）。

### Experiment 2：真实资源账本

**做什么**

- 建立 grant、reserve、spend、return、expire 事件；
- 计入 Router、Verifier 和通信开销；
- 做重复事件、失败、超时和中途终止故障注入；
- 使用属性测试验证余额不为负和总量关系。

**要证明**

> 多周期执行中资源不会凭空生成、重复扣减、越权转移或静默超支。

### Experiment 3：反馈驱动再分配

**做什么**

- 为模拟 Agent 设置未知的真实转换效率；
- Router 只从逐周期反馈学习；
- 比较固定均分、贪心赢家和带探索的反馈策略；
- 中途改变任务需求和 Agent 效率；
- 比较固定温度调度和动态温度调度。

**要证明**

> 在计入控制成本后，反馈能否提高单位资源任务收益，并在环境变化时重新配置。

### Experiment 4：反转路由与马太效应

**做什么**

- 对比任务选择 Agent、Agent 选择任务、双向匹配；
- 控制初始随机优势；
- 设置容量上限、最低预算和探索补贴；
- 观察长期任务覆盖与 Agent 被验证机会。

**要证明**

> 反转路由能否减少早期赢家锁定，并且最终效率损失可接受。

**注意**

它只能证明机会分配改善，不能单独证明信用分配正确。

### Experiment 5：信用归因

**做什么**

- 构造包含串行、并行、冗余和误导贡献的任务图；
- 比较末端奖励、依赖图回传、移除消融和近似反事实；
- 注入延迟反馈与错误 Verifier；
- 验证信用暂缓与回滚机制能否防止错误信用固化；
- 检查信用是否落到真正必要的路径。

**要证明**

> 系统能否在可接受成本下，将任务进展归因给关键 Agent、证据和通信边，而不是只奖励最后输出者。并且当 Verifier 出错时，暂缓与回滚机制能否将错误信用的影响限制在可接受范围内。

### Experiment 6：本地模型任务信号

**做什么**

- 引入一个同构小模型；
- 比较规则、embedding 和 LLM 需求提取；
- 比较环境验证、模型评价和 Agent 自评；
- 测量跨提示、跨种子和跨任务稳定性。

**要证明**

> 本地模型能否产生足够稳定、可校验的任务表示和反馈信号，驱动前述控制系统。

### Experiment 7：文本级多 Agent 闭环

**做什么**

- 使用可自动评分的小任务；
- 多个逻辑 Agent 共享同一模型；
- 使用结构化 JSON 传递证据；
- 接入分化、账本、反馈和反转路由；
- 与单 Agent、固定角色和固定预算比较。

**要证明**

> 数值模拟中的分工和能量反馈，能否转化为真实模型行为与最终任务收益。

### Experiment 8：通信拓扑

**做什么**

- 比较广播、固定流水线、按需通信和学习型拓扑；
- 对通信进行删除、置换和伪消息实验；
- 记录边际质量收益和通信成本。

**要证明**

> 基于任务依赖和反馈形成的稀疏有向拓扑，是否比固定拓扑更有效。

### Experiment 9：同构 latent communication

**做什么**

- 比较无通信、JSON、摘要、embedding、hidden state/KV；
- 固定模型、预算和任务；
- 测量质量、时延、内存、字节、失败和可审计性；
- 做信息删除与随机注入消融。

**要证明**

> latent communication 是否具有覆盖全部工程成本的净收益。

### Experiment 10：组织记忆与热启动

**做什么**

- 保存成功和失败组织快照；
- 在相似、部分相似和伪相似任务上加载；
- 校准热启动阈值；
- 检测负迁移并测试自动冷启动回退。

**要证明**

> 历史组织能否降低重新分化成本，同时不固化旧赢家和错误路径。

### Experiment 11：异构模型 latent 对齐

**前置门槛**

只有 Experiment 9 已证明同构 latent 通信有稳定净收益才开始。

**要证明**

> 跨架构投影相对文本中介是否仍有足够收益，并能承受表示漂移和训练成本。

它是独立研究课题，不属于初始 MVP。

## 17. Demo Task

### 17.1 目的

定义一个可在 5 分钟内向面试官展示架构核心想法的任务。即使只完成到 Experiment 2，此 demo 也能展示自组织分工、能量分配和反馈驱动的核心循环。

### 17.2 任务定义

**任务：给定一个有 5 个 TODO 的 Python 项目，让 3 个 Agent 自组织完成。**

示例项目：一个简易计算器模块，包含 5 个未实现函数：

1. `add(a, b)` — 基础算术；
2. `parse_expression(s)` — 字符串解析；
3. `evaluate(expr)` — 表达式求值（依赖 parse_expression）；
4. `format_result(val, precision)` — 结果格式化；
5. `run_repl()` — 交互式命令行（依赖 evaluate 和 format_result）。

### 17.3 任务特性

- **可验证的任务残差**：每个 TODO 对应一个需求维度，通过/不通过是二元判定，D_t 可精确计算；
- **真实的资源消耗**：每个 Agent 的 token 消耗可计量；
- **有意义的分工空间**：需求维度涵盖不同能力——算术、解析、求值、格式化、交互——Agent 可以在不同维度上分化；
- **依赖关系**：evaluate 依赖 parse_expression，run_repl 依赖 evaluate 和 format_result——天然形成通信和协作需求；
- **可扩展**：增加 TODO 数量或引入跨文件依赖可提升复杂度。

### 17.4 展示要点

Demo 运行时应可视化：

- 每个 Agent 的分配倾向向量（雷达图或条形图）；
- 任务残差随 cycle 的变化（哪些维度被满足、何时被满足）；
- 能量分配和消耗（每个 Agent 的预算、消耗、信用）；
- 通信图拓扑（谁向谁传递了什么证据）；
- 最终产物和测试通过率。

## 18. 总体验收与停止原则

### 18.1 架构获得支持的最低证据

至少需要证明：

1. 分化策略稳定优于简单基线（包括单 Agent）；
2. 任务反馈能可靠更新同一任务残差；
3. 资源账本正确且包含控制成本；
4. 反馈再分配提高单位资源收益；
5. 反转路由降低早期锁定；
6. 信用归因与真实因果贡献具有可接受一致性；
7. Verifier 错误不会导致错误信用不可逆固化；
8. 在真实本地模型任务上仍保留收益。

### 18.2 应当收缩或放弃机制的情况

**机制级：**

- 场动力学不优于贪心匹配或学习型 router；
- 反馈噪声导致预算持续震荡；
- Router 与 Verifier 成本超过节省的 Agent 成本；
- 信用归因无法区分关键贡献和表面输出；
- 信用暂缓与回滚无法在可接受成本内控制错误信用；
- 反转路由只是均分预算，没有改善长期发现能力；
- latent 通信不优于结构化文本；
- 热启动频繁产生负迁移。

**组织级：**

- 死锁频繁发生且自动恢复无效；
- 影子层级反复出现，容量上限无法控制；
- Groupthink 导致多样性持续下降，探索预算无法逆转；
- 级联失败导致系统在单点故障后无法恢复。

实验失败不等于整个愿景失败。它表示对应机制需要被简化、替换或删除。

## 19. 当前研究优先级

近期只做：

1. Experiment 0a：合成任务状态合同；
2. Experiment 0b：LLM 提取需求向量；
3. Experiment 1：分化与简单基线（含 MoE 风格学习型 router 对照）；
4. Experiment 1.5：最小真实模型验证（go/no-go 检查）；
5. Experiment 2：资源账本；
6. Experiment 3：反馈再分配；
7. Experiment 4：反转路由；
8. Experiment 5：模拟信用归因（含暂缓与回滚验证）。

完成 Experiment 0a-1 后，如果结果支持继续，准备 Demo Task。完成 Experiment 2-5 后，判断是否进入本地模型阶段。

当前最核心、也最可证伪的研究问题是：

> 一个依靠外部任务与真实计算预算维持的 Agent 组织，能否通过可验证反馈，持续把有限资源重新配置到具有更高边际贡献的能力和协作路径上，同时保持探索、避免赢家锁定，并让全部资源与贡献变化可追溯？
