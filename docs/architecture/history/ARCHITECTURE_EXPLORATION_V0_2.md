# 自组织 Agent 架构工程探索 v0.2

## 1. 文档定位

本文是实验规格，不是生产架构承诺。研究对象是：能否用连续动力系统形成有用的 Agent 分工，并在任务质量不下降的前提下减少重复计算和通信。

当前不主张用场动力学替代整个 Agent runtime。即使连续分化有效，以下机制仍需要离散、可审计的控制状态：

- 权限和副作用审批；
- 工具调用的开始、成功、失败和超时；
- 预算扣减和终止；
- 失败恢复与结果提交。

因此，当前更准确的表述是：**场动力学是候选的分工与资源分配策略，不是完整运行时。**

## 2. 核心研究问题

### 2.1 主问题

给定一个可分解任务、若干初始相近的 Agent 和有限预算，连续状态演化能否产生：

1. 对任务需求的充分覆盖；
2. Agent 之间较低的工作重复；
3. 稳定、可复现的角色分配；
4. 相对简单基线更高的质量成本比。

### 2.2 不作为成功证据的现象

- capability vectors 彼此远离；
- 图结构变稀疏；
- 状态变化率下降；
- 输出看起来具有不同风格；
- 多个 Agent 自称承担了不同角色。

这些只能证明状态发生了变化，不能证明产生了有效分工。

## 3. 概念收缩与术语定义

生物学类比用于提出机制，不作为正确性证据。每个概念必须落到可观测量。

| 原术语 | 当前工程定义 | 可观测量 |
|---|---|---|
| 形态发生素 | 任务需求向量或需求矩阵 | 维度、权重、来源 |
| Capability Vector | Agent 对任务需求维度的当前承担倾向 | 向量值、变化量 |
| Identity Vector | 跨周期保持的通信/路由标识 | 稳定性、漂移率 |
| 场 | 从群体状态聚合出的控制信号 | 聚合规则、输入输出 |
| 侧向抑制 | 对功能重叠的连续惩罚 | 相似度、惩罚值 |
| 能量 | 显式计算预算账本 | token、FLOPs 估计、时延或调用次数 |
| 凋亡 | 调度器根据规则停止 Agent | 停止原因、剩余预算 |
| 骨架固化 | 高频有效交互被缓存为候选路由先验 | 命中率、收益、淘汰规则 |

“能量”不能同时泛指梯度、注意力、token 和钱。每个实验只能选择一种主计量单位，并单独报告其他成本。

## 4. 修订后的状态模型

### 4.1 任务需求

任务不再只编码成一个不可解释的 embedding。Phase 0 使用带名称的需求向量：

\[
r = (r_1, r_2, \ldots, r_d), \qquad r_k \ge 0
\]

例如代码安全任务可包含：依赖发现、漏洞判断、影响分析、补丁生成、测试验证和报告。后续可以研究由 embedding 或 LLM 生成需求，但生成结果必须映射回可评估的需求集合。

### 4.2 Agent 状态

每个 Agent 的最小状态为：

\[
z_i(t) = \{c_i(t), q_i(t), e_i(t)\}
\]

- \(c_i\)：capability allocation，表示当前承担倾向；
- \(q_i\)：该 Agent 对各需求维度的观测质量或效用估计；
- \(e_i\)：剩余预算。

原文称 capability 与 identity “正交”，但给出的 identity 动量更新会让二者趋近，而不是数学正交。v0.2 暂时删除“正交”主张。只有通信拓扑确实需要跨周期稳定标识时，才加入 identity，并将其定义为慢变量而非正交变量。

## 5. 动力学假设

### 5.1 当前实验方程

Phase 0 使用三个可分离的力：

\[
c_i(t+1) = \operatorname{Norm}\left(c_i(t) + \eta [F_{task}^i + F_{cohesion}^i + F_{diversity}^i]\right)
\]

其中：

\[
F_{task}^i = \beta(r-c_i)
\]

\[
F_{cohesion}^i = \gamma(\Phi-c_i), \qquad \Phi=\frac{1}{N}\sum_i c_i
\]

\[
F_{diversity}^i = \frac{\lambda}{N-1}\sum_{j\ne i}
\exp\left(\frac{\cos(c_i,c_j)-1}{\tau}\right)(c_i-c_j)
\]

这是一种可执行的启发式动力学，不宣称等价于原文损失函数的严格梯度。向量归一化是显式的数值稳定约束。

### 5.2 当前已知限制

1. `F_diversity` 仍需要两两比较，复杂度为 \(O(N^2d)\)。平均场只用于 cohesion，并没有消除侧向抑制的两两成本。
2. 所有 Agent 被同一个任务向量吸引，可能出现整体坍缩；抑制过强则可能产生与任务无关的均匀散开。
3. 余弦差异只表示方向不同，不表示分工互补。
4. 当向量接近零时余弦梯度不稳定，因此必须定义范数下界或归一化规则。
5. 参数 \(\lambda,\tau,\gamma,\eta\) 之间存在耦合，不能只展示单个成功样例。

### 5.3 后续可能替代侧向抑制的目标

更贴近业务目标的形式不是“Agent 彼此不同”，而是“群体覆盖需求且减少重复”：

\[
J(C;r) = L_{uncovered}(C,r)
+ \lambda L_{redundancy}(C)
+ \mu L_{cost}(C)
\]

后续应比较直接优化该目标与生物启发动力学的差异。如果简单优化器更稳定、更便宜，就没有必要保留复杂类比。

### 5.4 能量不是一次注入，而是闭环控制

原始方案主要描述了任务进入时的初始预算注入：TRouter 解析任务、生成需求信号并分配总预算。这个过程只有前向流，没有说明系统如何根据执行结果重分配预算。更完整的循环应当是：

1. **外部注入**：任务、用户或环境提供需求 \(r_t\) 和真实预算 \(E_{in,t}\)。
2. **内部配置**：Router 根据当前 capability、历史信用和探索需求得到分配比例 \(a_i(t)\)。
3. **执行消耗**：Agent 执行工作并消耗预算 \(k_i(t)\)，产生产物和可验证证据。
4. **环境作用**：产物改变任务状态，例如发现事实、通过测试、暴露冲突或减少剩余需求。
5. **反馈评估**：Verifier 将变化转换为正确性、覆盖增量、新颖性和成本效率等信号。
6. **信用分配**：判断哪些 Agent、证据和通信边对状态改进有边际贡献。
7. **组织重塑**：更新 capability、通信权重和下一周期的预算分配，淘汰无效路径或为不确定方向保留探索预算。
8. **结束或再注入**：任务完成则冷却；仍有残余需求时，外部控制器决定是否注入下一批真实预算。

这里必须区分**真实能量**和**反馈信号**：

- 真实能量是可消耗的计算预算，例如推理 token、GPU 时间、调用次数或货币成本；
- 反馈不是凭空产生的新能量，而是控制后续能量流向的信号；
- 已消耗的算力不能“回收”，只有尚未使用的预算可以重新分配；
- 如果任务反馈触发了更多计算，那仍然属于外部控制器的新一轮能量注入。

这避免了“做得好便产生能量”的隐喻混淆。更准确的说法是：**有效工作获得更高的后续预算分配权，而不是创造了计算资源。**

### 5.5 最小能量账本

令 \(e_i(t)\) 为 Agent 可用余额，\(a_i(t)\) 为本周期获得的预算，\(k_i(t)\) 为实际成本：

\[
e_i(t+1) = e_i(t) + a_i(t)E_{in,t} - k_i(t)
\]

系统级守恒检查为：

\[
E_{available}(t+1) = E_{available}(t) + E_{in,t}
- \sum_i k_i(t) - k_{control}(t)
\]

其中 \(k_{control}\) 包含 Router、Verifier、通信和状态维护本身的成本。控制层不能被当成免费计算。

反馈形成信用值而非能量：

\[
g_i(t) =
w_q\Delta Quality_i
+ w_c\Delta Coverage_i
+ w_n Novelty_i
- w_r Redundancy_i
- w_k Cost_i
\]

下一周期可用一种带探索项的分配策略：

\[
a_i(t+1) = \operatorname{Softmax}\left(
\frac{\hat g_i(t) + b_i(t) - p_i(t)}{T}
\right)
\]

- \(\hat g_i\)：平滑后的历史信用；
- \(b_i\)：不确定性或探索奖励，防止早期赢家永久垄断预算；
- \(p_i\)：冗余、风险或违规惩罚；
- \(T\)：分配温度。

公式只是首个可测试控制器，不预设它是最终机制。

### 5.6 三种反馈时间尺度

反馈不应被压成一个总分：

| 时间尺度 | 反馈来源 | 作用 |
|---|---|---|
| 周期内 | 新证据、冲突、工具结果、局部验证 | 改变当前任务的剩余需求和下一步预算 |
| 任务结束 | 最终测试、用户评价、完整性检查 | 计算本次组织与 Agent 的边际贡献 |
| 跨任务 | 相似任务长期表现、负迁移记录 | 更新热启动先验和 Router 参数 |

周期内反馈必须优先使用可验证的环境变化，而不是 Agent 对自身表现的主观打分。任务结束反馈可用于慢变量更新，但不能事后篡改本次运行的成本账本。

### 5.7 能量闭环仍待解决的问题

1. **信用分配**：最终成功可能来自多个串行贡献，不能把全部奖励只给最后一个 Agent。
2. **延迟反馈**：早期发现的证据可能到任务结束才显出价值。
3. **指标投机**：Agent 可能优化容易得到奖励的代理指标，而不是任务真实目标。
4. **探索饥饿**：纯粹奖励赢家会让尚未被验证的生态位永久失去预算。
5. **验证成本**：Verifier 本身消耗能量，过度验证可能抵消多 Agent 收益。
6. **负反馈震荡**：即时大幅削减预算可能导致 Agent 反复退出和恢复。
7. **外部反馈可信度**：用户反馈、自动测试和 LLM judge 的噪声及权威级别不同。
8. **任务残差定义**：需要从反馈中明确计算“还有哪些需求没有满足”，否则反馈不能形成下一周期的形态信号。

因此，能量循环的核心不是设计一个奖励分数，而是同时解决预算守恒、任务残差、信用分配、探索和反馈可信度。

## 6. 对原始文档关键主张的修正

### 6.1 平均场不自动带来 O(N)

MF-MARL 研究表明，在特定多智能体强化学习设定中，可以用邻域平均作用近似群体交互。但这不是对任意 Agent 系统的通用保证，也不能覆盖当前显式两两侧向抑制。只有在用聚类中心、局部密度或采样近似替代两两项后，才可以重新测量复杂度。

### 6.2 群体方差下降不是分化收敛条件

从相近初始态发生分化时，群体方差可能上升。工程稳态至少需要同时观察：

- 平均状态更新量低于阈值；
- 角色/需求分配在连续若干周期内不变；
- 任务覆盖没有下降；
- 冗余和成本不再明显改善；
- 没有周期性振荡。

### 6.3 Identity 并不天然形成有向协作拓扑

仅使用 identity 相似度：

\[
w_{ij}=\operatorname{Softmax}_j(v_i^\top v_j)
\]

偏向连接相似 Agent，表达的是同质性而非能力互补。它也不能自然推出“分析 → 修复 → 报告”这种依赖方向。通信边至少需要结合：

- 发送方当前产物类型；
- 接收方所需输入类型；
- 子任务依赖；
- 历史交互的边际收益。

因此，拓扑是否涌现必须通过信息增益或下游质量验证，不能只看边变稀疏。

### 6.4 Expert Choice 与 Token Choice 不能直接移植

这两个概念来自 MoE 内部的 token—expert 路由。Agent 任务分配的对象可能是需求、证据、子任务或工具调用，并非 token。可以借鉴其负载均衡思想，但必须重新定义：

- 谁进行选择；
- 被选择的工作单元是什么；
- 容量约束是什么；
- 一个工作单元是否允许多个 Agent；
- 分配质量如何获得反馈。

在这些合同明确前，不应预设 Cycle 0–1 必须 Expert Choice、Cycle 4 后必须 Token Choice。

### 6.5 Amdahl 定律不能直接产生专门化收益 S

Amdahl 定律描述并行部分与串行部分对整体加速比的限制，不直接估计“专才比通才好多少”。v0.2 将其拆成两个独立量：

- `parallel_fraction`：可独立执行工作的比例；
- `specialization_gain`：专用执行者相对于通用执行者的实测质量成本增益。

后者必须从基准任务或历史观测估计，不能仅靠任务描述推断后当作真实值。

### 6.6 不再声明理论完善度百分比

“理论完善度 85%”和“工程就绪度 40%”没有可复现的评分尺度。v0.2 改用主张状态：

- `defined`：已有明确变量和接口；
- `implemented`：已有可运行实现；
- `validated`：在预注册指标上优于基线；
- `rejected`：实验未达到停止条件；
- `open`：仍为研究问题。

## 7. 是否需要本地部署小模型

### 7.1 结论

**需要，但不是现在立刻需要，也不应一开始部署多种模型。**

Phase 0 只验证动力学和指标，纯 NumPy 足够。本地小模型应在 Phase 1 引入，用来回答两个新问题：

1. capability/task signals 能否从真实文本任务和执行行为中稳定提取；
2. 结构化文本通信与 latent communication 是否存在可测的质量成本差异。

### 7.2 为什么本地模型有价值

- 可以固定模型版本、权重、随机种子和 decoding 配置；
- 可以直接调用模型 `forward()` 并请求逐层 hidden states；
- 可以插入 hooks、读取 KV cache、训练小型 projection/adapter；
- 避免把 API 供应商不可见的内部实现误当成可控实验变量；
- 可在相同输入上反复运行，便于消融实验。

Hugging Face Transformers 的模型输出支持在配置开启时返回各层 hidden states。这里证明的是“可以访问张量”，不是“张量可直接跨 Agent 使用”。后者仍需要定义层选择、token 对齐、压缩、注入位置和训练目标。

### 7.3 第一版本地模型实验配置

第一轮只使用**同一个小型 decoder-only 模型的多个逻辑 Agent 实例**：

- 建议规模：约 0.5B–3B，具体取决于本机可用内存；
- 相同权重、相同 tokenizer、相同推理精度；
- 每个 Agent 通过不同上下文、任务分配和可见证据形成差异；
- 先用 `Transformers` 直接推理，而不是只暴露文本 API 的服务层；
- 先比较结构化 JSON 消息、句向量消息和同构 hidden-state 消息；
- 不在第一轮做异构模型投影。

使用同构模型可以把“跨模型对齐”这一大变量暂时排除。若同构 hidden-state 通信都不能稳定优于结构化文本，就不应继续投入异构对齐。

### 7.4 不适合立即本地化的部分

- 不需要为了 Phase 0 下载模型；
- 不需要一开始搭建分布式推理服务；
- 不需要同时运行多个独立权重副本；
- 不需要先训练自编码器或跨模型 adapter；
- 不需要把模型 hidden size 直接当成 capability vector 维度。

### 7.5 Hidden-state 通信的最低对照实验

所有通信方式使用相同模型、任务、最大计算预算和运行次数：

| 组别 | 通信方式 | 目的 |
|---|---|---|
| A | 无通信 | 测量多 Agent 本身是否有收益 |
| B | 结构化 JSON | 强解释性基线 |
| C | 文本摘要 | 常规 Agent 基线 |
| D | pooled embedding | 低带宽连续表示 |
| E | hidden state / KV 注入 | 待验证方案 |

必须报告最终任务质量、端到端时延、峰值内存、通信字节数、生成 token 数和失败率。不能只报告 token 减少，因为 latent tensors 也有显存、带宽和处理成本。

## 8. Latent communication 的风险与判定

LatentMAS 等工作说明 latent collaboration 是可研究方向，但近期消融研究也提示：跨 Agent transfer 未必始终贡献收益。因此本文将其视为开放假设，而非既定优势。

主要风险：

- 不同层的表示语义不同；
- 不同 tokenizer 和架构没有自然 token 对齐；
- 直接注入可能使接收模型分布外；
- 隐态通道难以审计，也可能携带非预期信息；
- projection 的训练数据可能把任务答案而非通信协议编码进去；
- KV cache 的体积可能远大于简短文本消息；
- 同一模型不同量化版本也可能发生表示漂移。

进入异构模型实验前必须满足：同构 latent 组在多随机种子上稳定优于文本基线，收益覆盖显存与工程复杂度成本，并且能够通过信息删除/置换消融证明接收方确实使用了发送方信息。

## 9. 分阶段实验路线

### Phase 0：无模型动力学

状态：`implemented`，尚未 `validated`。

目标：证明连续分化至少优于无抑制、随机、固定角色和贪心分配基线。

必须补齐：

- 参数扫描与多随机种子；
- 覆盖、冗余、振荡、收敛和成本指标；
- 非均匀需求、Agent 少于需求、Agent 多于需求等边界条件；
- 预注册的成功和停止条件。

### Phase 0B：无模型能量反馈闭环

状态：`open`。

使用可完全控制的模拟任务，让每个 Agent 对不同需求维度具有隐藏的真实效率。Router 看不到该真值，只能根据逐周期反馈学习预算分配。

该阶段依次验证：

1. **账本守恒实验**：证明预算不会凭空生成、重复扣减或超支。
2. **反馈有效性实验**：证明有反馈的分配相对固定均分能提高单位成本覆盖率。
3. **信用延迟实验**：证明串行贡献不会让最后执行者独占信用。
4. **探索保留实验**：证明系统在早期误判后仍能发现更优 Agent/生态位。
5. **环境变化实验**：中途改变任务需求，验证能量能重新路由，而不是被历史赢家锁死。
6. **验证开销实验**：将 Router 和 Verifier 成本计入账本，判断闭环净收益是否仍为正。

Phase 0B 要证明的不是“奖励可以改变行为”，而是：**在真实控制成本计入后，反馈驱动的再分配是否比固定预算策略带来更高的任务收益，并且不会导致垄断、震荡或预算失真。**

### Phase 1A：本地模型作为信号提取器

模型只负责把任务或执行结果映射为可解释需求/效用，不传 hidden states。比较规则提取、embedding 和 LLM 提取的稳定性。

### Phase 1B：文本级逻辑 Agent

使用同一个本地小模型，执行可自动评分的微型任务。动力系统只分配任务，不控制权限和工具状态。

### Phase 2：同构 latent communication

比较无通信、JSON、摘要、embedding 和 hidden-state/KV 通信。此阶段需要可访问模型内部张量的本地推理。

### Phase 3：热启动与路由记忆

只在前述机制成立后保存组织快照。相似度阈值不预设为 0.70/0.95，而通过验证集校准，并检测负迁移。

### Phase 4：异构 latent alignment

这是独立研究课题，不是 MVP 的自然延伸。需要训练数据、对齐目标、跨架构注入接口和严格消融。

## 10. 评估协议

### 10.1 基线

- 单 Agent；
- N 个独立 Agent，最终投票或选择；
- 随机分配；
- 固定角色；
- 贪心覆盖；
- 场动力学但无侧向抑制；
- 完整场动力学。

### 10.2 核心指标

- `task_score`：任务最终质量；
- `coverage`：需求被有效产物覆盖的比例；
- `semantic_redundancy`：不同 Agent 产物的语义和证据重叠；
- `marginal_contribution`：移除某 Agent 后任务分数下降量；
- `allocation_stability`：连续周期的分配变化；
- `cost`：选定主单位下的预算消费；
- `wall_time` 与 `peak_memory`；
- `failure_rate`。

### 10.3 统计要求

- 每个配置运行多个固定种子；
- 报告均值、离散程度和原始结果；
- 参数范围在看结果前登记；
- 保留失败运行，不只展示最佳轨迹；
- 将调参任务与最终评估任务分开。

## 12. 近期执行顺序

1. 完成 Phase 0 分化基线、参数扫描和结果导出。
2. 完成 Phase 0B 能量账本、反馈再分配和需求突变实验。
3. 选择可自动评分的小任务集，不先选择开放式代码审计。
4. 检查本机资源后选择一个 0.5B–3B 同构模型。
5. 先做本地文本级 Agent，建立质量与成本基线。
6. 再开放 hidden states，逐项做通信消融。

在 Phase 0 未优于简单基线前，不下载模型也不扩展架构；在文本级多 Agent 未产生收益前，不研究 latent communication。
