# 自组织 Agent 能量场架构：工程探索规格 v0.3

## 0. 文档状态

本文是一份可证伪的研究架构，不是生产系统设计，也不代表这些机制已经成立。

它综合了以下核心想法：

1. Agent 不应只能由预设角色和固定工作流组织；
2. Agent 可以从相近初态出发，根据任务需求动态分化；
3. 计算资源有限，分工和组织结构应由资源流塑造；
4. 任务路由只是外部能量的第一次注入，执行反馈必须参与后续能量再分配；
5. 任务表示与任务反馈应共享同一套任务指标和状态坐标；
6. 分化初期应使用反转路由和容量约束，避免早期随机优势演化成马太效应；
7. 历史有效的分工、通信和转换路径可以形成可修正的组织记忆；
8. hidden-state 通信、异构对齐和完整“能量货币”都属于待验证研究问题，而不是当前前提。

当前工程边界：所有探索都位于本独立目录，不与 OpenPilot 主运行时、权限系统或 metadata 合同集成。

## 1. 架构核心命题

### 1.1 总命题

将多 Agent 系统视为一个开放的资源转换系统：外部任务、环境和用户向系统提供目标、信息和计算预算；Agent 消耗资源、产生证据和产物；环境反馈改变任务状态；系统根据可验证贡献重新分配后续预算，并由此形成、维持或重塑组织结构。

简化循环如下：

```text
外部目标与真实预算
        ↓
任务状态与任务残差
        ↓
分化、路由与预算配置
        ↓
Agent 执行、通信与工具作用
        ↓
产物改变环境和已知状态
        ↓
验证、反馈与信用归因
        ↓
更新任务残差、能力估计和组织结构
        ↓
继续注入、重新配置、冷却或终止
```

### 1.2 当前最小研究命题

在不降低任务质量的前提下，反馈驱动的连续分化和预算再分配，能否比固定角色、固定均分或简单贪心策略获得：

- 更完整的任务覆盖；
- 更少的重复工作；
- 更高的单位资源收益；
- 更好的环境适应性；
- 可接受的控制成本与稳定性。

### 1.3 不应提前宣称的结论

当前不宣称：

- 场动力学能够替代完整 Agent runtime；
- 平均场已经把复杂度从 `O(N²)` 降为 `O(N)`；
- 向量分散等价于有效分工；
- hidden-state 通信天然优于结构化文本；
- 所有资源和价值都能被无损压缩成一个通用标量；
- 系统已经具备生物意义上的生命、自主性或真正代谢。

## 2. 世界模型：开放系统而非封闭状态机

系统必须从外部获得：

- 目标和约束；
- 初始事实与环境状态；
- 计算、时间、工具访问等真实资源；
- 执行结果和验证信号；
- 必要时的用户评价与新增任务。

因此它不是能够自行产生能量的封闭系统。它可以做的是：

1. 记录能量从哪里进入；
2. 决定能量流向哪些 Agent 和任务维度；
3. 记录能量经过怎样的转换过程；
4. 测量转换后任务状态发生了什么变化；
5. 根据反馈调整下一轮资源配置；
6. 保存或淘汰有效的转换路径。

这里的“自组织”指内部配置策略能够适应任务和反馈变化，不表示系统脱离外部目标、预算与安全边界。

## 3. 能量概念的分层

“能量”必须拆成不同层次，否则同一个词会同时指算力、价值、信用和注意力，无法形成可验证模型。

### 3.1 第一层：真实资源

真实资源是会被消耗、具有单位并可记账的量，例如：

- 输入与输出 token；
- GPU/CPU 时间；
- 墙钟时间；
- 内存和通信字节；
- 工具调用次数；
- 货币成本；
- 人工审核时间；
- 风险额度。

真实资源不必全部转换成一个单位。底层优先使用向量账本：

\[
R_t=(tokens, gpu\_seconds, wall\_time, bytes, money, risk, \ldots)
\]

### 3.2 第二层：任务势能或任务残差

任务势能不是物理能量，而是当前状态距离目标状态还有多远。

令：

- \(G\)：目标和约束；
- \(S_t\)：在时刻 \(t\) 已被证据支持的任务状态；
- \(D_t=Residual(G,S_t)\)：尚未满足的任务需求。

Agent 的产物只有在改变 \(S_t\) 并减少 \(D_t\) 时，才产生可观察的任务进展。

### 3.3 第三层：贡献信用

贡献信用表示某个 Agent、证据、工具调用或通信边对任务进展的边际贡献。信用不是新产生的计算能量，而是一种影响未来资源分配的记账凭证。

### 3.4 第四层：有效能量价格

如果调度器需要把多维资源和贡献临时转换成一个可比较分数，应使用与当前任务状态有关的动态投影：

\[
E_{effective}(t)=p_t^\top R_t
\]

\(p_t\) 类似当前任务下的动态交换率或影子价格。例如任务临近截止时，时间成本权重会上升；事实不足时，新证据价值会上升；高风险操作前，验证资源价值会上升。

因此，“统一能量货币”在当前架构中的可行定义是：

> 底层保留多维、带来源和转换路径的资源账本；上层根据任务状态产生动态结算价格，用于局部决策，而不是把世界永久压缩成一个固定标量。

### 3.5 一碗米饭所揭示的问题

一碗米饭不能只由热量描述。它包含太阳、水、土壤、养分、土地、时间、劳动、知识、机械、运输、储存、烹饪和损耗；食用后又会根据人的身体状态转换为活动、组织修复、储存、热量和废物。

它说明：

- 资源具有类型、来源、品质和时间属性；
- 每次转换都有条件、效率、产物和损耗；
- 同一资源对不同接收者具有不同的边际作用；
- 物理守恒、经济成本和目标价值不是同一个量；
- 一个最终数字无法反向恢复完整因果链。

Agent 系统不需要先解决世界范围的一般能量建模，才能开始实验。最小探索只需在局部任务内明确资源单位、转换过程、任务残差和结算规则。

## 4. 任务表示与反馈的统一

### 4.1 它们是同一状态空间的两个方向

任务表示回答：

> 当前目标是什么？哪些需求仍未满足？

任务反馈回答：

> 执行后，哪些需求被满足、恶化或暴露出新的缺口？

因此二者必须使用同一套指标坐标，而不是 Router 产生一套任务 embedding、Verifier 再产生一个无关总分。

### 4.2 最小任务状态

一个任务状态至少包含：

```text
Goal
  ├─ requirements       需求及权重
  ├─ constraints        不允许违反的条件
  ├─ acceptance_rules   完成判定
  └─ resource_limits    总预算和风险边界

ObservedState(t)
  ├─ supported_facts    有证据支持的事实
  ├─ artifacts          已产生的产物
  ├─ verified_results   验证结果
  ├─ conflicts          未解决冲突
  └─ uncertainty        未知或低可信区域

Residual(t)
  ├─ unmet_requirements
  ├─ unresolved_risks
  ├─ missing_evidence
  └─ new_requirements
```

### 4.3 反馈更新

执行动作 \(A_i(t)\) 后：

\[
(S_t,R_t) \xrightarrow{A_i} (S_{t+1},R_{t+1},Artifacts,Evidence)
\]

Verifier 不直接奖励“生成了多少内容”，而是根据证据更新任务状态：

\[
D_{t+1}=Residual(G,Update(S_t,Evidence,Artifacts))
\]

任务进展可以写成多维变化：

\[
\Delta D_t=D_t-D_{t+1}
\]

如果产生了新的风险或需求，对应维度可以为负或新增，不能强行认为每轮执行都让任务单调变好。

### 4.4 反馈可信度层级

反馈来源具有不同权威级别：

1. 可重复环境事实，如编译、单元测试、传感器读数；
2. 形式规则和静态检查；
3. 独立模型或多评审一致性；
4. Agent 自评；
5. 用户偏好或开放式评价。

反馈记录必须保存来源、证据、置信度和适用范围。低可信反馈可以影响探索，但不应直接覆盖高可信事实。

## 5. Agent 与组织状态

### 5.1 Agent 最小状态

每个 Agent \(i\) 的研究状态暂定为：

\[
Z_i(t)=\{C_i,A_i,Q_i,U_i,B_i,H_i\}
\]

- \(C_i\)：长期或跨任务的能力先验；
- \(A_i\)：当前任务上的分配倾向；
- \(Q_i\)：在各任务需求上的观测效用；
- \(U_i\)：能力和效用估计的不确定性；
- \(B_i\)：当前真实资源余额；
- \(H_i\)：缓慢变化的历史身份或关系状态，可选。

必须区分“Agent 想承担什么”“Router 给它什么”和“它实际擅长什么”。Capability vector 不能同时承担以上所有语义。

### 5.2 Identity 的修正

原方案声称 capability 与 identity 正交，但动量跟随公式只产生快慢变量，不保证数学正交。

当前定义改为：

> Identity 是用于跨周期稳定识别和关系建模的慢状态；只有实验证明通信拓扑需要它时才保留。

Identity 不能单独决定通信，因为相似身份更容易形成同质连接，而任务协作通常需要能力互补和产物依赖。

### 5.3 转换函数比角色标签更核心

Agent 的价值可以表达为条件转换能力：

\[
T_i:(Input,State,Resources)\rightarrow(Artifacts,Evidence,StateChange,Cost,Loss)
\]

系统真正要学习的是：在当前状态下，哪个 Agent 能用何种成本把哪些输入转换成多少可验证任务进展，而不是给 Agent 贴上永久角色名称。

## 6. 三层组织结构

### 6.1 细胞内树层

职责：保存单 Agent 私有状态和局部执行过程。

包含：

- 当前需求和局部计划；
- 私有工作记忆；
- 工具输入输出；
- 局部置信度；
- 资源余额与成本；
- 尚未共享的候选证据。

该层保持树形或嵌套 metadata，不因场模型而强制图化。

### 6.2 共享证据图层

职责：保存跨 Agent 可验证的事实、产物、依赖和贡献路径。

候选节点：

- RequirementNode；
- EvidenceNode；
- ArtifactNode；
- ActionNode；
- FeedbackNode；
- AgentSnapshotNode。

候选边：

- supports / contradicts；
- produced_by；
- consumed_by；
- depends_on；
- verified_by；
- contributed_to。

所谓节点“能态”在第一阶段只表示调度优先级或近期激活度，不能与节点内部真的保存模型 hidden states 混为一谈。

### 6.3 组织场层

职责：根据任务残差、群体状态和反馈形成控制信号。

包含：

- Task Residual Field；
- Population Capability Field；
- Redundancy/Inhibition Field；
- Resource Allocation Field；
- Risk and Constraint Field；
- Feedback/Credit Field。

场层输出的是分配倾向和控制参数，实际执行、审批、预算扣减与终止仍由离散控制器完成。

## 7. 分化动力学

### 7.1 Phase 0 当前启发式

\[
A_i(t+1)=Norm(A_i(t)+\eta[
F_{task}^i+F_{cohesion}^i+F_{diversity}^i])
\]

其中：

\[
F_{task}^i=\beta(D_t-A_i)
\]

\[
F_{cohesion}^i=\gamma(\Phi-A_i),\qquad
\Phi=\frac{1}{N}\sum_i A_i
\]

\[
F_{diversity}^i=\frac{\lambda}{N-1}\sum_{j\ne i}
\exp\left(\frac{cos(A_i,A_j)-1}{\tau}\right)(A_i-A_j)
\]

它只是稳定、可执行的第一版假设，并非严格从某个全局损失推导出的最终方程。

### 7.2 必须修正的目标

纯余弦排斥只会鼓励不同，不保证互补。最终目标更接近：

\[
J=
L_{uncovered}
+\lambda L_{redundancy}
+\mu L_{resource}
+\rho L_{risk}
+\xi L_{instability}
\]

需要将动力学方案与直接优化、贪心匹配和市场式分配比较。如果简单方法更稳定且效果相同，应接受场动力学没有额外工程价值。

### 7.3 收敛定义

不能用群体方差下降表示分化完成，因为从相近初态分化时方差可能上升。

候选收敛条件应同时包含：

- 状态更新量持续低于阈值；
- 分配关系在多个周期内稳定；
- 需求覆盖不再明显提高；
- 单位成本收益不再明显提高；
- 没有周期性振荡；
- 没有关键需求长期饥饿。

## 8. 完整能量循环

### 8.1 外部注入

Energy Authority 根据任务价值、风险和总资源限制提供：

- 任务目标；
- 初始资源包；
- 每种资源的单位；
- 使用范围和过期条件；
- 是否允许后续追加预算。

任务路由本身不创造资源。

### 8.2 分配与消耗

令 \(B_i(t)\) 为 Agent 余额，\(G_i(t)\) 为本轮 grant，\(K_i(t)\) 为实际成本：

\[
B_i(t+1)=B_i(t)+G_i(t)-K_i(t)
\]

系统级检查：

\[
B_{system}(t+1)=B_{system}(t)+E_{in}(t)
-\sum_iK_i(t)-K_{router}(t)-K_{verifier}(t)-K_{communication}(t)
\]

已消耗的资源不能回收。未使用 grant 可以退回共享池；新增执行必须由尚未使用的共享预算或新的外部注入支付。

### 8.3 反馈与信用

候选局部信用：

\[
Credit_i(t)=
w_dContribution_i(\Delta D_t)
-w_kCost_i
-w_rRedundancy_i
-w_sRisk_i
\]

其中 `Contribution` 不能只根据最后输出判断，而需要沿证据与依赖路径归因。

### 8.4 再分配

下一轮资源份额可以使用：

\[
Share_i(t+1)=Softmax\left(
\frac{\widehat{Credit_i}+Explore_i-Penalty_i}{T}
\right)
\]

- `Credit`：已观测边际贡献；
- `Explore`：不确定性奖励和最低探索补贴；
- `Penalty`：冗余、风险、失败或违规；
- `T`：控制集中度的温度。

这不是唯一可能的算法，只是用于验证反馈闭环是否有效的最小控制器。

### 8.5 三种反馈时间尺度

| 时间尺度 | 主要来源 | 主要作用 |
|---|---|---|
| 周期内 | 工具结果、新证据、冲突、局部测试 | 更新当前残差并重新路由 |
| 任务结束 | 最终验收、整体质量、用户评价 | 计算组织与贡献路径的最终信用 |
| 跨任务 | 相似任务长期表现、失败和负迁移 | 更新能力先验、热启动和路由参数 |

## 9. 反转路由与马太效应控制

### 9.1 马太效应来源

如果任务始终选择当前得分最高的 Agent：

```text
早期随机领先
→ 获得更多任务和预算
→ 获得更多被观察与成功的机会
→ 评分进一步上升
→ 其他 Agent 无法证明能力
```

这会把观测机会误当成真实能力。

### 9.2 早期：反转路由

分化初期让 Agent 从任务需求池中选择工作，而不是让任务只选择当前赢家：

- 每个 Agent 有最低探索预算；
- 每个 Agent 有容量上限；
- 每个需求允许有限数量的重复探索；
- 未知能力方向获得不确定性补贴；
- 当前高分 Agent 不能占据全部高价值需求。

反转路由解决的是“获得验证机会”的公平性，不直接解决信用归因。

### 9.3 中期：双向约束匹配

- 任务根据历史效用偏好 Agent；
- Agent 根据能力倾向和探索价值偏好需求；
- Router 在覆盖、容量、风险和成本约束下求匹配；
- 对不确定或高风险需求保留有限竞争。

### 9.4 后期：任务主导利用

- 剩余任务需求选择预计边际收益最高的 Agent；
- 强化冗余抑制；
- 停止为低贡献路径分配主预算；
- 保留少量探索预算，以处理环境变化或估计漂移。

### 9.5 阶段切换条件

不使用固定 Cycle 数作为唯一切换条件。切换依据包括：

- 能力估计不确定性是否下降；
- 任务需求是否已被初步覆盖；
- Agent 相对转换效率是否可区分；
- 分配是否趋于稳定；
- 是否出现需求突变或新证据。

环境变化时，系统可以从利用阶段重新回到探索或匹配阶段。

## 10. 通信拓扑

### 10.1 通信边的形成依据

通信不能只依赖 identity 或 capability 相似度。候选边权应考虑：

- 发送方产物类型；
- 接收方当前输入需求；
- 子任务依赖方向；
- 证据可信度；
- 历史信息增益；
- 通信成本；
- 重复和风险。

### 10.2 通信是否有价值的判定

必须通过消融验证：

- 删除消息后下游质量是否下降；
- 打乱发送方后结果是否变化；
- 接收方是否引用或使用了关键证据；
- 通信收益是否覆盖 token、时延和带宽成本。

图变得稀疏或有向，不自动等于通信有效。

### 10.3 阶段化通信假设

- 早期：低成本广播任务残差和公共事实；
- 中期：按产物—需求兼容性建立候选边；
- 后期：只传递下游明确需要的证据与产物；
- 冷却后：保留可审计文本/结构化证据，不默认长期保存 hidden state。

## 11. 本地模型和 latent communication

### 11.1 本地模型引入时机

无模型阶段先验证分化、反馈、预算和信用机制。只有这些机制至少优于简单基线，才引入本地模型。

第一轮建议：

- 一个约 0.5B–3B decoder-only 模型；
- 多个逻辑 Agent 共用相同权重和 tokenizer；
- 固定模型版本、推理精度和随机配置；
- 先使用结构化 JSON 通信；
- 暂不处理异构模型对齐。

### 11.2 本地模型第一阶段职责

模型首先只用于：

- 从任务描述提取候选需求；
- 从产物提取候选事实和证据；
- 将反馈映射回任务残差坐标；
- 在明确分工下执行可自动评分的微型任务。

模型输出必须经过结构验证或环境验证，不能把自评直接当成信用。

### 11.3 latent communication 对照组

| 组别 | 通信方式 |
|---|---|
| A | 无通信 |
| B | 结构化 JSON |
| C | 文本摘要 |
| D | pooled embedding |
| E | hidden state 或 KV 注入 |

需要统一比较任务质量、端到端时延、峰值内存、通信字节、生成 token、失败率和可审计性。

只有同构 latent 通信稳定优于结构化文本，并通过删除和置换消融证明消息被真正使用，才进入异构模型对齐。

## 12. 组织记忆与热启动

组织快照候选内容：

- 任务需求与环境条件；
- Agent 能力后验及其不确定性；
- 有效分工和通信路径；
- 能量成本与任务收益；
- 失败模式和负迁移记录；
- Router 与 Verifier 配置版本。

热启动不能使用未经校准的固定阈值。必须验证：

- 相似度是否预测了正迁移；
- 加载旧组织后是否更快；
- 最终质量是否下降；
- 发现不适配后能否退回冷启动；
- 历史赢家是否压制新生态位。

记忆不是永久固化骨架，而是具有证据、适用范围、衰减和撤销条件的路由先验。

## 13. 仍待解决的基础问题

### 13.1 表示问题

1. 如何从开放式任务构造稳定、可验证的需求坐标？
2. 新需求在执行中出现时，如何扩展坐标而不破坏历史状态？
3. capability 是能力、偏好、分配还是表现估计？如何彻底分离？
4. 不同任务之间的 capability 是否可比较？
5. 哪些信息应该是向量，哪些必须保持符号和证据结构？

### 13.2 度量问题

1. 如何衡量开放式任务的真实完成度？
2. 如何区分语言表面差异与真实工作差异？
3. 如何测量信息增益、语义冗余和边际贡献？
4. 多维资源何时可以投影成单个动态价格？
5. 用户偏好、环境事实和模型评价发生冲突时如何处理？

### 13.3 动力学问题

1. 任务吸引、群体凝聚和侧向抑制在什么参数范围内稳定？
2. 如何避免坍缩、无意义均匀散开和周期振荡？
3. 如何证明或至少经验刻画收敛域？
4. 显式侧向抑制仍为 `O(N²)`，如何近似且控制损失？
5. 环境变化后，系统能否快速解除旧分工？

### 13.4 信用分配问题

1. 串行贡献如何跨多个 Agent 回传？
2. 延迟反馈如何归因给早期行动？
3. 多个 Agent 共同产生产物时如何分配信用？
4. Verifier 不完美时如何防止错误信用固化？
5. 如何防止 Agent 针对代理指标投机？

### 13.5 能量与市场问题

1. 哪些资源必须守恒，哪些只需记账？
2. Router、Verifier 和通信成本如何完整计入？
3. 动态价格由谁生成，如何防止不稳定和操纵？
4. 最低探索补贴如何设置，既避免赢家锁定又不长期浪费？
5. 风险、权限和不可逆副作用能否被价格化，还是必须使用硬约束？

### 13.6 工程与安全问题

1. 如何保证每一次资源变动可审计？
2. 连续策略如何与离散工具状态、审批和失败恢复共存？
3. hidden-state 通信如何检测越权信息和不可解释信号？
4. 模型、量化或 tokenizer 变化时如何识别表示漂移？
5. 怎样定义可靠的停止、回滚和降级路径？

## 14. 工程探索路线与待证明命题

每个阶段只回答有限问题。前一阶段失败时，不因为愿景完整而自动进入后一阶段。

### Experiment 0：指标和状态合同

**做什么**

- 定义带名称的需求向量；
- 定义目标、观测状态、任务残差和反馈事件；
- 构造若干完全可计算的模拟任务；
- 为状态更新编写不变量和属性测试。

**要证明**

> 任务表示和反馈是否能够使用同一坐标，并在执行后一致地更新任务残差。

**失败条件**

- 同一产物在相同状态下得到不一致反馈；
- 任务残差无法解释为什么完成或未完成；
- 新证据无法追溯到状态变化。

### Experiment 1：无模型分化

**做什么**

- 比较单 Agent、随机、固定角色、贪心覆盖、无抑制动力学和完整动力学；
- 扫描 Agent 数、需求维度和动力学参数；
- 使用多随机种子和非均匀需求；
- 检测坍缩、分散、振荡与需求饥饿。

**要证明**

> 连续分化能否在维持覆盖的同时减少冗余，并优于简单基线。

**停止条件**

如果它不能稳定优于贪心或固定角色，不进入复杂 LLM 分化。

### Experiment 2：真实资源账本

**做什么**

- 建立 grant、reserve、spend、return、expire 事件；
- 计入 Router、Verifier 和通信开销；
- 做重复事件、失败、超时和中途终止故障注入；
- 使用属性测试验证余额不为负和总量关系。

**要证明**

> 多周期执行中资源不会凭空生成、重复扣减、越权转移或静默超支。

### Experiment 3：反馈驱动再分配

**做什么**

- 为模拟 Agent 设置未知的真实转换效率；
- Router 只从逐周期反馈学习；
- 比较固定均分、贪心赢家和带探索的反馈策略；
- 中途改变任务需求和 Agent 效率。

**要证明**

> 在计入控制成本后，反馈能否提高单位资源任务收益，并在环境变化时重新配置。

### Experiment 4：反转路由与马太效应

**做什么**

- 对比任务选择 Agent、Agent 选择任务、双向匹配；
- 控制初始随机优势；
- 设置容量上限、最低预算和探索补贴；
- 观察长期任务覆盖与 Agent 被验证机会。

**要证明**

> 反转路由能否减少早期赢家锁定，并且最终效率损失可接受。

**注意**

它只能证明机会分配改善，不能单独证明信用分配正确。

### Experiment 5：信用归因

**做什么**

- 构造包含串行、并行、冗余和误导贡献的任务图；
- 比较末端奖励、依赖图回传、移除消融和近似反事实；
- 注入延迟反馈与错误 Verifier；
- 检查信用是否落到真正必要的路径。

**要证明**

> 系统能否在可接受成本下，将任务进展归因给关键 Agent、证据和通信边，而不是只奖励最后输出者。

### Experiment 6：本地模型任务信号

**做什么**

- 引入一个同构小模型；
- 比较规则、embedding 和 LLM 需求提取；
- 比较环境验证、模型评价和 Agent 自评；
- 测量跨提示、跨种子和跨任务稳定性。

**要证明**

> 本地模型能否产生足够稳定、可校验的任务表示和反馈信号，驱动前述控制系统。

### Experiment 7：文本级多 Agent 闭环

**做什么**

- 使用可自动评分的小任务；
- 多个逻辑 Agent 共享同一模型；
- 使用结构化 JSON 传递证据；
- 接入分化、账本、反馈和反转路由；
- 与单 Agent、固定角色和固定预算比较。

**要证明**

> 数值模拟中的分工和能量反馈，能否转化为真实模型行为与最终任务收益。

### Experiment 8：通信拓扑

**做什么**

- 比较广播、固定流水线、按需通信和学习型拓扑；
- 对通信进行删除、置换和伪消息实验；
- 记录边际质量收益和通信成本。

**要证明**

> 基于任务依赖和反馈形成的稀疏有向拓扑，是否比固定拓扑更有效。

### Experiment 9：同构 latent communication

**做什么**

- 比较无通信、JSON、摘要、embedding、hidden state/KV；
- 固定模型、预算和任务；
- 测量质量、时延、内存、字节、失败和可审计性；
- 做信息删除与随机注入消融。

**要证明**

> latent communication 是否具有覆盖全部工程成本的净收益。

### Experiment 10：组织记忆与热启动

**做什么**

- 保存成功和失败组织快照；
- 在相似、部分相似和伪相似任务上加载；
- 校准热启动阈值；
- 检测负迁移并测试自动冷启动回退。

**要证明**

> 历史组织能否降低重新分化成本，同时不固化旧赢家和错误路径。

### Experiment 11：异构模型 latent 对齐

**前置门槛**

只有 Experiment 9 已证明同构 latent 通信有稳定净收益才开始。

**要证明**

> 跨架构投影相对文本中介是否仍有足够收益，并能承受表示漂移和训练成本。

它是独立研究课题，不属于初始 MVP。

## 15. 总体验收与停止原则

### 15.1 架构获得支持的最低证据

至少需要证明：

1. 分化策略稳定优于简单基线；
2. 任务反馈能可靠更新同一任务残差；
3. 资源账本正确且包含控制成本；
4. 反馈再分配提高单位资源收益；
5. 反转路由降低早期锁定；
6. 信用归因与真实因果贡献具有可接受一致性；
7. 在真实本地模型任务上仍保留收益。

### 15.2 应当收缩或放弃机制的情况

- 场动力学不优于贪心匹配；
- 反馈噪声导致预算持续震荡；
- Router 与 Verifier 成本超过节省的 Agent 成本；
- 信用归因无法区分关键贡献和表面输出；
- 反转路由只是均分预算，没有改善长期发现能力；
- latent 通信不优于结构化文本；
- 热启动频繁产生负迁移。

实验失败不等于整个愿景失败。它表示对应机制需要被简化、替换或删除。

## 16. 当前研究优先级

近期只做：

1. Experiment 0：任务状态、残差和反馈合同；
2. Experiment 1：分化与简单基线；
3. Experiment 2：资源账本；
4. Experiment 3：反馈再分配；
5. Experiment 4：反转路由；
6. Experiment 5：模拟信用归因。

完成这些无模型实验后，再判断是否下载和部署本地小模型。

当前最核心、也最可证伪的研究问题是：

> 一个依靠外部任务与真实计算预算维持的 Agent 组织，能否通过可验证反馈，持续把有限资源重新配置到具有更高边际贡献的能力和协作路径上，同时保持探索、避免赢家锁定，并让全部资源与贡献变化可追溯？
