# Biofield 架构方向复盘：从自分化到中心 Router

日期：2026-07-21

本文是一份架构决策记录。它回答 Biofield 从最初的自分化、自组织构想演化到旧规格时，哪些概念被澄清了，哪些局部决策权被逐步收归中心，以及重新回到原始研究方向时应保留什么、恢复什么。

本复盘的核心判断已经于 2026-07-21 被 [当前架构规格](./ARCHITECTURE_EXPLORATION_FINAL.md) 和 [实验执行协议](../experiments/EXPERIMENT_PROTOCOL.md) 采纳。本文仍保留推理过程和历史审查价值；发生实现或实验细节冲突时，以当前架构规格和实验协议为准。

## 1. 核心结论

后期架构已经解决了早期“能量”概念混用问题。真正偏离原始方向的不是资源、残差和信用仍然混在一起，而是局部决策权逐步被收归中央：

> 架构在概念上越来越严谨，在权力结构上却越来越中心化；最终科学问题从“组织如何通过局部相互作用涌现”滑向了“中心控制器如何在全局信息和约束下优化组织”。

Harness 原本是为了让 Biofield 可执行、可观测、可审计和可证伪而逐渐形成的实验支架。它本应负责事实、资源和安全边界，但在后续演化中进一步取得了任务分解、探索机会、分配、阶段切换、通信传播和恢复策略的决定权，因而越过了从“约束环境”到“组织智能”的边界。

## 2. 能量概念已经在后期分开

### 2.1 Blueprint 的早期混用

原始 Blueprint 中的“能量”同时指向：

- 任务诱导梯度；
- 注意力和计算；
- Agent 预算；
- 图节点激活；
- 竞争、修剪和凋亡信号。

这种表达保留了生物直觉，但无法直接形成可验证合同。

### 2.2 v0.2 的概念收缩

v0.2 明确规定：能量不能同时泛指梯度、注意力、token 和钱；每个实验必须选择明确的资源单位。它还区分了真实资源和反馈信号：有效工作获得的是未来预算分配权，而不是创造新的计算资源。

### 2.3 v0.3 的四层模型

v0.3 将原来的能量隐喻拆成：

1. 真实资源；
2. 任务残差；
3. 贡献信用；
4. 动态价格。

任务残差和反馈共享同一坐标，信用只影响未来资源，真实消耗不可回滚。这已经不再是早期的混用状态。

### 2.4 v0.5.1 与最终规格的进一步收敛

v0.5.1 再次强调真实资源、任务进展和贡献信用是三种不同量。最终规格进一步限制 `shadow price`：只有明确约束优化中的对偶变量才使用该名称，其他权重只称为 priority weight。

因此，后期架构的问题不能再概括成“能量概念混乱”。它真正需要复盘的是：谁感知、谁选择、谁承诺、谁调整自身、谁决定组织结构。

## 3. 原始 Biofield 命题

原始构想包含两个同时存在的方向。

第一个方向是自分化、自组织：

- Agent 从相近初态出发；
- 每个 Agent 保有私有状态；
- Agent 响应任务场、共享场和其他 Agent；
- 微小差异被局部动力学放大；
- 角色不是预先写入 Prompt，而是运行中形成；
- 通信拓扑随着分化涌现；
- 组织结构由反复有效的能量和信息路径塑造。

第二个方向是中心控制的种子：

- TRouter 解析任务；
- TRouter 生成形态发生素；
- TRouter 决定侧向抑制参数；
- TRouter 切换路由阶段；
- TRouter 分配总预算并决定热启动。

因此 Blueprint 并非完全去中心化，但它仍把分化描述为 Agent 在场中的同步局部演化。后续偏移不是凭空出现，而是 Blueprint 中的中心控制种子在解决工程问题时不断扩大，最终覆盖了局部动力学原本承担的决策空间。

## 4. 决策权迁移时间线

| 阶段 | 仍然存在的局部权力 | 中心新增的权力 | 方向变化 |
|---|---|---|---|
| Blueprint | 私有状态、局部判断、能力演化、通信拓扑形成 | 任务解析、场参数、预算、路由阶段和热启动 | 自组织构想与中央 TRouter 并存 |
| v0.2 | Agent 保留 capability、质量估计和局部执行 | Router 根据全局状态计算分配比例，Verifier 解释结果 | 自分化开始被重新表达为反馈分配 |
| v0.3 | 初期 Agent 从需求池选择工作；Agent 保存私有计划和候选证据 | 中期 Router 完成约束匹配，中心维护残差、信用和预算 | 严谨性与局部权力相对平衡 |
| v0.4 | Agent 生成候选证据、决定是否请求提升、保有局部历史 | Router 负责任务分解、维度新增、初始任务差异、匹配、恢复和通信重路由 | 中心开始决定分化所需的大多数输入条件 |
| v0.5 | Agent 作为真实模型执行者和状态载体 | 公共 `AllocationDecision`、allocator 比较、风险门和统一实验 DAG | 研究问题转向中心 allocator 的优劣 |
| v0.5.1 | Agent 仍有执行历史和能力后验 | 中心计算 residual、reliable coverage、congestion、exploration 和 allocation | 场被正式定位为候选 allocator |
| v0.5.2 | Agent 在叙述上仍可“选择需求” | 中心决定探索总额、上下限、并发上限、阶段策略和降级 | 局部选择被压缩成中心可控的分配变量 |
| 最终规格 | 私有树层保存计划、记忆、工具结果和历史 | 控制平面与 Allocation 状态机拥有任务本体、资源、验证、阶段切换、重探索和终态权力 | 局部主体退化为被观测、被估计、被分配的执行单元 |

## 5. 最终规格中的结构性不一致

最终规格仍保留了以下叙述：

> 初期由 Agent 从需求池选择工作。

但它没有为这种选择定义可执行合同。当前公共合同主要包含：

- `TaskSpec`；
- `AllocationDecision`；
- `ActionObservation`；
- `FeedbackEvent`；
- `ResourceEvent`；
- `ExperimentResult`。

缺少的局部决策合同包括：

- `LocalFieldObservation`：Agent 实际能感知哪些场信号；
- `AgentIntent`：Agent 想处理哪个需求，以及为什么；
- `AgentBid`：Agent 愿意投入多少自身容量或资源；
- `AgentCommitment`：Agent 正式承诺承担什么；
- `AgentRefusal`：Agent 基于局部判断拒绝不适合或不安全的工作；
- `CommunicationOffer` / `CommunicationRequest`：Agent 自主选择共享、请求或连接对象；
- `LocalStateUpdate`：Agent 如何根据自身行动和局部反馈改变其表型。

在这些合同缺失的情况下，“Agent 选择需求”只是一句叙述。真正可运行的流程仍是中心先产生 Allocation，Agent 再执行；Agent 没有正式渠道表达自身感知、意图、承诺和拒绝。

## 6. 偏移为何逐渐发生

这次偏移不是因为某一版突然否定自组织，而是每一次工程完善都解决了真实问题：

- 为了解释任务是否完成，引入 Residual 和 Verifier；
- 为了资源正确性，引入 Ledger；
- 为了错误反馈，引入 taint、revalidation 和 quarantine；
- 为了防止赢家锁定，引入探索配额与份额上下限；
- 为了避免未知能力被错误占位，引入 ReliableCoverage；
- 为了控制阶段和恢复，引入 Cold/Warming/Mature/Recovery；
- 为了处理不完备任务，引入中心化 schema 管理。

每个机制单独看都合理，但它们共同形成了同一种补偿模式：

> 每发现一种不确定性，就在中心增加一个判断器；每发现一种风险，就在中心增加一个约束；每发现一种涌现失败，就由中心增加一个调度规则。

最终，场从 Agent 可感知并响应的共享介质变成了中心计算 Allocation 的输入；Agent 从局部控制器变成了全局优化问题中的执行节点。

## 7. Harness 应有的边界

### 7.1 Harness 可以集中掌握的权力

- 公布外部目标、验收条件和硬约束；
- 维护可审计的任务、证据和资源事实；
- 验证权限与副作用边界；
- 拒绝非法、超预算或冲突的动作；
- 执行资源结算、幂等、超时和终态；
- 记录实验事件并保证可重放；
- 在系统失控时执行 fail-safe 停止。

这些是环境、事实和安全权威，不等于组织智能。

### 7.2 Harness 不应默认掌握的权力

- 为每个 Agent 选择具体需求；
- 直接生成全部 Agent—需求 Allocation；
- 决定每个 Agent 的探索方向；
- 替 Agent 判断自身是否适合某项工作；
- 决定通信对象和信息传播路径；
- 直接决定局部表型如何更新；
- 在环境变化后指定谁替代谁。

Harness 可以否决非法行动，但不应替 Agent 产生全部合法行动。

## 8. 回到原始方向的建议

最适合重新出发的概念锚点不是未经修正的 Blueprint，而是 v0.3：

- 保留 v0.3 已经完成的真实资源、任务残差、信用与价格分层；
- 保留 Harness 的账本、验证、事件和终态合同；
- 恢复 v0.3 中 Agent 从需求池选择工作的局部权力；
- 吸收 v0.4 的证据提升、冲突保留、信用暂缓和回滚；
- 保留后期关于误差、taint、replay 和负结果的实验纪律；
- 放弃由中心直接生成完整 Allocation 矩阵作为 Biofield 的默认形态。

恢复后的最小闭环应是：

```text
Harness 发布目标、硬约束与可信环境状态
        ↓
Field 传播局部可感知的残差、拥塞、风险与资源压力
        ↓
Agent 根据私有状态形成 Intent / Bid / Refusal
        ↓
局部承诺经过硬约束仲裁，而不是由中心重新优化
        ↓
Agent 执行、选择通信并产生证据
        ↓
Harness 验证事实、结算资源并更新可观测环境
        ↓
Agent 根据局部反馈更新自身状态，组织继续演化
```

中心可以处理多个局部承诺之间的硬冲突，但不应把仲裁重新扩张成全局最优分配。

## 9. 需要重新回答的 Biofield 研究问题

后续研究不应首先问“FieldAllocator 是否优于 UCB”，而应先问：

1. 相近初态的 Agent 是否能基于不同局部经历形成稳定但可逆的功能差异？
2. 局部 Agent 是否能根据场信号自主选择需求，而不是接受中心分配？
3. 多个局部选择能否在只有硬约束仲裁的情况下形成充分覆盖并减少重复？
4. Agent 失败或环境变化后，组织能否在没有中心显式指定替代者的情况下恢复？
5. 通信拓扑能否由局部信息需求和证据供给形成，而不是由 Router 计算？
6. 局部自主带来的适应性收益，是否覆盖冲突、重复、通信和收敛成本？

如果 Agent 被移除后必须由中心明确指定替代者，系统仍是中心调度。如果场发生变化后，其他 Agent 能根据自身状态和局部信号改变承诺并恢复覆盖，才构成自组织与再生的证据。

## 10. 修正后的项目关系

项目不应被理解成两套并列架构，而应理解成：

```text
Harness：实验与安全支架
    └── 为 Biofield 提供事实、资源、验证和可重放环境

Biofield：核心研究命题
    └── 研究局部主体如何通过场、反馈和相互作用形成组织
```

Harness 即使在 Biofield 假设失败时也可能具有独立工程价值，但这不应改变项目最初希望回答的科学问题。

最终需要恢复的不是某条旧动力学公式，而是局部决策权：

> Biofield 的核心不应是中心如何计算更好的组织，而应是局部单元如何在共享场和有限约束下生成组织。
